# 社内情報流通革命プラットフォーム

---

## 1. 事業ビジョン（統合版）

**「社内の全情報を、自社の金庫の中で生きた知識に変える。」**

プライベートLLM（オープンソースAIを自社サーバーに展開）と、社内情報の自動キャプチャ・構造化を組み合わせた**完全クローズド型・組織知能化サービス**。

議事録を書かない。質問を繰り返さない。退職者の知識が消えない。そして社内情報は一切外に出ない。日本企業が抱えるセキュリティ不安・情報断絶・属人化という3つの病巣を、ひとつのプラットフォームで解決する。

---

## 2. 解決する課題

### 日本企業の情報流通、3つの病巣

**病巣①：情報の外部流出リスク（顕在化している恐怖）**

ChatGPT・Copilot等のクラウドAIに社内情報を入力すれば、その情報は外部サーバーに送信される。法務・医療・製造・金融の現場では、この一点だけでAI導入が止まっている。便利なツールだとわかっていても、使えない。

**病巣②：情報の断絶と摩擦（見えにくいが深刻なコスト）**

- 会議が終わる → 誰かが議事録を書く → 誰かが読む → わからなければ聞く → 答える人を探す
- この「書く・読む・聞く・答える」という連鎖が毎日何百回も繰り返されている
- Slack・メール・会議・ドキュメントに情報が分散し、必要な情報にたどり着くのに時間がかかる
- 情報の鮮度が落ちるにつれ、誰も読まない資料が積み上がる

**病巣③：属人化と知識の消滅（最も深刻・最も語られない問題）**

- エース社員が退職する = その人が10年かけて蓄積した判断・経緯・暗黙知が消える
- 後継者が同じ失敗を繰り返す。同じ質問を一から調べる
- これは「情報漏洩の逆バージョン」だ。情報が外に出るのではなく、情報が会社から消える

## 3. プロダクト設計

### プロダクト名（仮）：**VAULT BRAIN（ヴォルトブレイン）**

「自社の金庫の中にある、組織の脳」というコンセプトから。

### コア機能

| 機能カテゴリ | 内容 |
|------------|------|
| **自動キャプチャ** | 会議音声のリアルタイム書き起こし・要約（Whisper等）、チャットツール連携、メール連携、文書アップロード |
| **知識ベース構築** | 全情報を自動でベクトルDB（Chroma/Qdrant）に格納・タグ付け・関係性マッピング |
| **自然言語Q&A** | 「先月のA社との合意事項は？」「この設計の経緯は？」を自然言語で即座に回答（RAG方式） |
| **議事録自動生成** | 会議音声から自動で構造化議事録を生成・配信（確認のみでOK） |
| **アクセス権限管理** | 役職・部署・プロジェクト単位での閲覧権限。全アクセスログ記録 |
| **退職者引き継ぎ** | 退職予定者の関与情報を自動でパッケージ化し、後継者に引き継ぎ |
| **ダッシュボード** | 組織内の情報フロー可視化、未解決質問の把握、知識ギャップ検出 |

### 技術構成

```
[入力層]
  音声 → Whisper（ローカル動作）
  文書 → OCR + PDFパーサー
  チャット連携 → Slack/Teams API（オプション）

[処理層（全て自社サーバー内）]
  LLM → LLaMA3 / Mistral / DeepSeek-R1（オープンソース）
  ベクトルDB → Qdrant / Chroma（オンプレ）
  オーケストレーション → LangChain / LlamaIndex

[インフラ層]
  オンプレサーバー or プライベートクラウド（VPC内完結）
  インターネット接続不要モード対応

[UI層]
  Webアプリ（社内アクセス専用）
  チャットUI（Slack風インターフェース）
  管理者コンソール
```

### UI概念

- 普段使いの窓口は**チャットUI1本**。「聞く」だけでいい
- 管理者向けに**ナレッジマップ**（組織内の情報の繋がりをビジュアル化）
- 週次サマリーの自動配信（「今週の重要決定事項」「未回答の積み残し」）

## 4. セキュリティアーキテクチャ

### 設計思想：セキュリティを「制約」ではなく「競争優位」として設計する

#### ① 外部漏洩ゼロの技術的根拠

- **LLMの推論処理を自社サーバー内で完結**。OpenAI APIを一切使わない
- **Whisperをローカル動作**させることで、会議音声が外部に出ない
- オプション：**エアギャップ動作モード**（インターネット接続なしで全機能動作）
- 全通信はVPN/専用線内に閉じる

#### ② 内部統制の技術実装

| 統制項目 | 実装方法 |
|---------|---------|
| アクセス権限 | RBAC（Role-Based Access Control）＋属性ベース制御 |
| 監査ログ | 「誰が・いつ・何を参照したか」を全件記録・改ざん不可 |
| 退職者対応 | アカウント即時無効化 + 退職者関連情報の引き継ぎパッケージ自動生成 |
| データ分離 | 部署・プロジェクト単位でのデータ論理分離 |
| 暗号化 | 保存データ・通信データの暗号化（AES-256 / TLS 1.3） |

#### ③ 組織の記憶保全という第三のセキュリティ

従来の「情報セキュリティ」は外部流出防止のみを指す。このプロダクトは**「知識の消滅リスク」を内部セキュリティの一形態**として定義し直す。

- エース社員の退職 = 「会社にとって最大の情報漏洩」という逆説を訴求
- 属人化スコアの可視化（「この情報、A氏しか持っていません」アラート）
- 後継育成期間中の知識転移モニタリング

## 5. ビジネスモデル

### 料金体系（SaaS型）

| プラン | 対象 | 月額（概算） | 内容 |
|--------|------|------------|------|
| **スタータープラン** | 〜30名 | 15万円〜 | 基本Q&A + 議事録自動生成 + 権限管理 |
| **スタンダードプラン** | 〜100名 | 40万円〜 | 全機能 + チャット連携 + ナレッジマップ |
| **エンタープライズプラン** | 100名〜 | 100万円〜 | カスタム構成 + 専任サポート + SLA保証 |

**初期導入費（別途）**：サーバー調達・セットアップ・初期データ移行。50〜200万円想定。

### 収益構造

- **メイン収益**：月額SaaSフィー（継続課金・解約率が低い領域）
- **サブ収益**：追加ストレージ・追加ユーザーライセンス
- **オプション収益**：カスタム連携開発・既存システムとのAPI統合
- **コンサル収益**：AI活用推進支援・社内定着化支援

### 顧客獲得戦略

1. **自社実績をプロトタイプとして使う**（フリーレン秘書システム等）
2. 士業・医療への紹介営業（顧問弁護士・会計士ネットワーク経由）
3. 商工会議所・業界団体での事例セミナー
4. パートナー制度（IT企業・コンサル会社への再販）

## 6. 競合分析と差別化

### 競合マップ

| カテゴリ | 代表サービス | 弱点 |
|---------|------------|------|
| クラウドAI（外部処理） | ChatGPT Enterprise, Microsoft Copilot | 情報が外部サーバーに送信される |
| 社内wiki・ナレッジ管理 | Notion, Confluence | LLMなし。検索は人間がする |
| 国内プライベートAI | 一部SI企業提供 | 高コスト・カスタム開発のみ・中小に届かない |
| 議事録ツール | Notta, Otter.ai | クラウド処理・議事録単機能 |

### 差別化の核心

**「完全クローズド × 組織知能化 × 中小対応」の三角形を同時に満たすサービスは現時点で存在しない。**

- 完全クローズドのみ → SI企業のスポット開発（高価・属人的）
- 組織知能化のみ → Notionや社内wikiの延長（クラウド依存）
- 中小対応のみ → 機能が薄い

このプロダクトは「SI企業がやっていたカスタム開発をSaaS化・低価格化」するポジションを取る。

## 7. ターゲット市場と参入順序

### 優先順位と根拠

**フェーズ1（0〜12ヶ月）：士業**

- 弁護士・会計士・税理士は「守秘義務が法的義務」であり、クラウドAI利用に強い制限
- 事務所規模が小さく意思決定が速い（代表者1人の決断で導入決定）
- 「議事録自動生成」「相談内容の参照」への需要が明確
- 渡邊カンパニーの既存ネットワークから紹介営業が可能

**フェーズ2（6〜18ヶ月）：医療・クリニック**

- 個人情報保護法・医療情報安全管理ガイドラインへの適合需要
- カルテ・患者対応記録の参照ニーズ
- 複数クリニックへの横展開がしやすい

**フェーズ3（12〜24ヶ月）：中小製造業**

- 技術・設計ノウハウの属人化問題が深刻
- 職人の退職・技術継承問題と直結する訴求が可能
- 導入後の定着率が高い（替えが効かない情報が蓄積されるため）

**フェーズ4（18ヶ月〜）：建設・不動産、金融・保険**

- 規制対応の観点から需要はあるが、意思決定が遅い
- フェーズ1〜3の実績を引き提げて攻める

## 8. MVP設計

**「最小で検証すべき仮説」：クローズド環境でのRAGチャットボットに、守秘義務業種が実際にお金を払うか**

### MVP構成（3ヶ月で作れるもの）

- Whisperによる会議音声書き起こし（ローカル動作）
- 書き起こしテキスト + アップロード文書のベクトルDB格納
- ローカルLLM（LLaMA3）によるQ&A応答
- シンプルなWebチャットUI（社内アクセス専用）
- 基本的なユーザー管理・ログ記録

**MVPで外すもの**（後回し）：ナレッジマップ・属人化スコア・チャット連携・多言語対応

### 検証指標

- 3社の士業事務所で3ヶ月のパイロット導入
- 週次利用回数・質問解決率・「これがなくなったら困る」スコア
- 有償継続意向の確認

## 9. 日本市場への普及戦略

### 「文化変革」を売らない。「リスク回避」を売る

日本企業に「議事録文化を変えましょう」と訴えても動かない。「このままではリスクがあります」なら動く。

**訴求軸の順序**：
1. **セキュリティリスク**（ChatGPTに入力すると漏れる） → 危機感
2. **コンプライアンスリスク**（守秘義務違反・個人情報保護法） → 義務感
3. **経営リスク**（エース退職 = 知識消滅） → 切迫感
4. **効率化メリット**（議事録・質問が消える） → 追加の魅力

### 普及の踊り場を越える施策

- **成功事例の早期公開**：1社目の導入事例を徹底的にドキュメント化し、業界誌・セミナーで発信
- **無料トライアル設計**：自社サーバーへのセットアップ支援込みで2週間無料（解約ハードルが高くなる仕掛け）
- **資格者団体との提携**：弁護士会・日本公認会計士協会・医師会系団体との協力関係構築
- **補助金連携**：IT導入補助金・DX推進補助金の活用をセット提案

## 10. リスクと対策

### 技術リスク

| リスク | 対策 |
|--------|------|
| ローカルLLMの精度がクラウドAIに劣る | 用途を「社内情報の参照・整理」に絞る（汎用推論は不要）。RAGで補う |
| サーバー調達・保守コスト | クラウドVPC（AWS/GCPのプライベート構成）も選択肢として提供 |
| 音声認識精度（方言・専門用語） | Whisperのファインチューニング + 辞書登録機能で対応 |
| LLMの幻覚（hallucination） | 回答に必ず「出典（どの会議・文書か）」を明示。参照元の透明性を担保 |

### 営業リスク

| リスク | 対策 |
|--------|------|
| 「うちには早い」という先送り | MVP＋パイロット提案で小さく始めやすくする |
| IT担当者がいない中小企業 | セットアップ・運用保守込みのマネージドサービスとして提供 |
| 競合の大手参入 | 中小・士業への深い業種特化と価格優位性で守る |

### 法的リスク

| リスク | 対策 |
|--------|------|
| 個人情報保護法への適合 | 「処理は自社内完結」をもって第三者提供に該当しないことを法的に整理 |
| 労働者のプライバシー（会議録音） | 録音・記録の同意取得フロー・利用規約を整備 |
| オープンソースLLMのライセンス | 商用利用可能なモデル（LLaMA3商用版・Mistral等）のみ採用 |

## 11. 渡邊カンパニーとの親和性

### 活かせる既存リソース

| 既存資産 | 活用方法 |
|---------|---------|
| **フリーレン秘書システム** | このプロダクトの縮小版として機能している。デモ・事例として最強の説得力 |
| **AI導入支援の実績** | 「自社でも使っている」「こう導入した」という実体験ベースの提案が可能 |
| **中小・中堅企業へのネットワーク** | スマホセールスや人材事業で構築した中小企業とのパイプ |
| **AIシステム開発ケイパビリティ** | MVP開発を内製できる。外注コストゼロで初期検証が可能 |
| **スマホショップコンサルの現場知見** | 「情報断絶・属人化」の課題は現場でも共通。事例として使える可能性 |

### 親和性の核心

渡邊カンパニー自身がこのプロダクトの「生きたプロトタイプ」だ。フリーレン秘書システムによる社内AI活用は、まさにこのビジョンの実装例に相当する。自社の実践を事例として語れる強みは、他社には絶対に真似できない。

## 12. 推奨アクション（優先順位付き）

### 最優先（今月中）

1. **プロダクト名・コンセプトの確定**
   - 「VAULT BRAIN」は仮称。競合サービス名との衝突確認・商標調査
   - 「社内の情報は、社内だけで完結する。」等のキャッチコピーを固める

2. **MVP開発スコープの確定**
   - Whisper + ローカルLLM + Qdrant + シンプルWebUIの最小構成を設計
   - 自社内での動作確認（フリーレン秘書システムとの比較）

### 高優先（1〜2ヶ月以内）

3. **士業3社へのヒアリング**
   - 「ChatGPTに入力しているか」「守秘義務の壁を感じているか」を確認
   - 具体的な情報参照ニーズのヒアリング（どんな情報を誰に聞いているか）

4. **MVPのパイロット提案準備**
   - 士業事務所向けのデモ動画・資料作成
   - パイロット提案（2週間無料 + セットアップ支援込み）の条件設計

### 中期（3〜6ヶ月）

5. **IT導入補助金の適用確認**
   - 2026年度のIT導入補助金対象要件に合わせたプロダクト設計の調整

6. **パートナー制度設計**
   - IT企業・コンサル会社への再販モデルの検討

## 展開案（3〜5案）

### 案A：士業特化SaaS（推奨案）
士業（弁護士・会計士・税理士）に完全特化したバーティカルSaaSとして展開。「守秘義務完全対応の議事録AI」として業界内での口コミ浸透を狙う。PMFが取れてから横展開。

**メリット**：市場が小さいため競合が少ない。意思決定者が明確。紹介が広がりやすい。
**懸念**：市場規模が限定的。エンタープライズへのスケールに時間がかかる。
**収益モデル**：事務所単位の月額SaaS。1事務所15〜30万/月。

### 案B：製造業特化（技術継承フォーカス）
中小製造業の技術継承問題を前面に出したサービス設計。「職人の頭の中を会社に残す」訴求。
**メリット**：「2025年問題・団塊世代引退」という時流に乗れる。補助金が手厚い。
**懸念**：現場への定着に時間がかかる。IT化が遅れているためオンボーディングコストが高い。

### 案C：医療クリニック特化
電子カルテと連携した患者情報参照・スタッフ間引き継ぎ効率化。
**メリット**：個人情報保護の必要性が自明。クリニックチェーンへの横展開が可能。
**懸念**：医療情報ガイドラインへの適合が厳格。競合の医療IT企業が強い。

### 案D：渡邊カンパニー自身をショーケースにしたドキュメンタリーマーケティング
このプロダクトの導入・活用過程を全公開し、「AI企業のリアルな実践」として発信。SNS・YouTube・ニュースレターで認知獲得してからサービス展開。
**メリット**：広告費ゼロで認知拡大。渡邊カンパニーのブランド価値も同時に上がる。
**懸念**：成果が出るまでに時間がかかる。内部情報の公開範囲の設計が必要。

### 案E：パートナーモデルによるホワイトラベル展開
IT企業・コンサル会社にホワイトラベルで提供し、彼らが自社クライアントに再販する。渡邊カンパニーはプラットフォーム提供者になる。
**メリット**：営業力を外部に委託できる。急速なスケールが可能。
**懸念**：価格競争になりやすい。品質管理が難しい。ブランドが立ちにくい。

---

## おすすめ案

**案A（士業特化SaaS）をコアに、案D（ドキュメンタリーマーケティング）を並走させる。**

理由：渡邊カンパニーが自社でこのプロダクトを使っているという事実は、最強の信頼証明になる。士業という「守秘義務×小規模×意思決定が速い」ターゲットでPMFを取りながら、その過程をコンテンツとして公開することで、認知と信頼を同時に獲得する。

## 🔍 ブリーフィング（CEOへ）
