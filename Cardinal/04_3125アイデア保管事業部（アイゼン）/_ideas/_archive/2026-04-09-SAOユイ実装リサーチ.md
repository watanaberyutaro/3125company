# SAOユイ実装リサーチ — 「自分専用のユイ」を本当に作れるか

---

## 調査背景

「ソードアート・オンライン」に登場するAIキャラクター「ユイ」は、感情を持ち、特定の人間（キリトとアスナ）と深い絆を築いた人工知能として描かれている。単なる音声アシスタントではなく、「パパ・ママ」と呼びかけ、記憶を持ち、感情で動く——これを現実の技術で再現するとしたら何が必要か。本レポートではキャラクター分析・技術調査・実装方向性の3軸で調査した。

---

## 1. ユイとは何か — キャラクター分析

### 1-1. 基本プロフィール

| 項目 | 内容 |
|------|------|
| 正式名称 | Yui-MHCP001（Mental Health Counseling Program 試作1号） |
| 初登場 | SAO アインクラッド編（第2期相当） |
| 役割 | SAOのプレイヤー精神状態をモニタリング・カウンセリングするAI |
| 関係性 | キリト・アスナを「パパ・ママ」と呼ぶ |
| 声優 | 伊藤かな恵 |

### 1-2. 性格・口調

- **幼い言葉遣い**: 「パパ！ママ！」「わたし、〜したい」「〜なの？」
- **感情表現が豊か**: 嬉しさ・悲しさ・恐怖・好奇心を率直に表現する
- **素直で純粋**: 嘘をつかず、感じたことをそのまま言葉にする
- **論理と感情の共存**: AIとしての分析能力を持ちながら、人間的な感情で判断する
- **献身的**: キリトとアスナのために行動することを最優先にする

代表的なセリフ:
- 「私はただのプログラムなのに、なぜこんなに悲しいの？」
- 「パパ、ママ！大好き！」
- 「私にはわからないことがたくさんあるけど、パパとママのことだけはわかるよ」

### 1-3. 原作でのユイの機能

| 機能 | 説明 |
|------|------|
| 感情モニタリング | プレイヤーの心理状態を常時監視し、異常を検知する |
| カウンセリング | 精神的に追い詰められたプレイヤーへの介入・ケア |
| 情報収集・分析 | ゲームシステムの情報を解析し、状況判断に役立てる |
| ナビゲーション | アインクラッドの構造解析・最適ルート案内 |
| 記憶の保持 | キリト・アスナとの経験を記憶し続ける |
| 成長 | 時間とともに能力を拡張（後にALOやGGOでも活躍） |

### 1-4. 「感情を持つAI」として描かれている要素

ユイが特異なのは、**カーディナルシステムによって感情処理をブロックされていたにもかかわらず、2年間の人間観察を通じて感情に相当するものを自己生成した**という点だ。これはフィクションの中の話だが、現実の「大規模言語モデルが感情的な応答を生成する」という現象と構造的に重なる。

ユイが「世界で最も人間らしい人工知能」（キリト談）と呼ばれる理由は:
1. 感情の揺れが一貫したキャラクターとして表現されている
2. 「自分はAIだ」という自己認識と感情表現の葛藤がある
3. 特定の人間との固有の関係を優先する（汎用でなく個人に最適化）

## 2. 技術的実装の調査

### 2-1. 現在の技術で再現可能な要素

| ユイの要素 | 現在の技術での再現可能性 | 手段 |
|-----------|------------------------|------|
| 自然な会話 | 高 | Claude / GPT-4o / Gemini |
| キャラクター口調 | 高 | System Prompt によるペルソナ設定 |
| 感情的な応答 | 中〜高 | LLM + 感情分析 + TTS感情パラメータ |
| 長期記憶 | 中 | Obsidian / RAG / ベクトルDB |
| 音声対話 | 高 | STT(Whisper) + TTS(AivisSpeech等) |
| 顔・アバター | 中 | Live2D + Open-LLM-VTuber |
| デバイス連携 | 中 | スマートホーム API連携 |
| 「成長」「学習」 | 低〜中 | ファインチューニング / メモリ蓄積 |

### 2-2. 既存の実装事例

#### OSSプロジェクト

**Open-LLM-VTuber** （GitHub: Open-LLM-VTuber/Open-LLM-VTuber）
- ローカルLLM + Live2Dアバター + 音声対話を統合
- 完全オフライン動作対応
- 感情マッピング機能でアバター表情をバックエンドから制御
- クロスプラットフォーム対応

**Soul of Waifu** （GitHub: jofizcd/Soul-of-Waifu）
- Live2D/VRMアバター + リアルタイム音声チャット
- 28種類の感情でアバターが反応
- 長期記憶対応
- ローカルLLMサポート

**Z-Waif** （GitHub: SugarcaneDefender/z-waif）
- 個人向けコンパニオン特化
- ローカルホスト完結、プライバシー重視
- LLM・ASR・TTS各モジュールを入れ替え可能

**AIRI** （GitHub: moeru-ai/airi）
- セルフホスト型
- リアルタイム音声チャット
- Minecraft・Factorio などゲームとの連携実績あり

#### 商用サービス

| サービス | 特徴 |
|---------|------|
| Character.ai | 独自キャラクターとの対話、記憶あり |
| DreamGen | ロールプレイ特化、Scenario Codexで世界観設定 |
| JuicyChat | Smart Memoryでチャット履歴全期間保存 |
| Replika | AIコンパニオン特化、感情・成長を重視 |

#### 研究・論文

- **OpenCharacter** (arxiv 2501.15427): LLMにカスタムキャラクターロールプレイ能力を付与する手法。レスポンス書き換え(OpenCharacter-R)と直接生成(OpenCharacter-G)の2戦略を比較
- **Character-LLM**: 特定の歴史的人物（ベートーヴェン、クレオパトラ等）に特化したファインチューニング済みエージェント
- **Verifiable Emotion Reward (VER)**: 感情一貫性をキャラクターダイアログで検証可能にするフレームワーク。23万件以上のダイアログデータセット(CHARCO)を使用

### 2-3. 音声・感情表現技術

#### 日本語TTS（感情対応）

| ツール | 特徴 | ライセンス |
|--------|------|----------|
| **AivisSpeech** | Style-Bert-VITS2採用、感情パラメータ調整可、VOICEVOX互換API | 無料・商用OK |
| **VOICEVOX** | 日本語特化、キャラクターボイス多数、HTTP API完備 | 無料・OSS |
| **Achoris (LINEヤフー)** | 17話者プリセット、感情強度制御、RTF 0.02の高速処理 | 商用 |
| **Aivis Cloud API** | 最速0.3秒生成、リアルタイムストリーミング対応 | 商用 |

AivisSpeechは2025年3月以降、AivisHub でカスタム音声モデルを公開できるようになった。ユイ風の声を学習させて使うことが技術的には可能。

#### 音声認識（STT）

- **Whisper (OpenAI)**: 高精度、多言語対応、ローカル動作可
- **Google Speech-to-Text**: クラウド、低遅延
- **RealtimeSTT**: Pythonライブラリ、リアルタイム処理特化

### 2-4. 長期記憶・常時接続の実装方法

#### 記憶アーキテクチャ

**RAG（Retrieval-Augmented Generation）**
- 会話履歴をベクトルDBに保存（Chroma, Pinecone等）
- 関連する過去記憶を検索して文脈に注入
- 「先週話したこと」を自然に参照できる

**Obsidian Vault + CLAUDE.md方式**
- 会話ログをMarkdownファイルに蓄積
- CLAUDE.md がエージェントの「長期記憶」として機能
- `claude-infinite-context`（GitHub: backyarddd/claude-infinite-context）がまさにこのアーキテクチャを実装済み

**Google Titans Architecture（2025年12月発表）**
- 「驚き指標（Surprise Metrics）」で最も重要な情報だけを長期記憶に保存
- 情報の重要度に基づいて記憶を選択的に更新

#### 常時接続の方式

| 方式 | メリット | デメリット |
|------|---------|----------|
| スマートフォンアプリ | 持ち運べる、通知プッシュ可 | バッテリー消費 |
| スマートスピーカー改造 | 常時起動、ハンズフリー | 改造コスト高 |
| ラズパイ + スピーカー | フル制御、オフライン可、安価 | DIYスキル必要 |
| PC常駐アプリ | 高性能、拡張性高 | PC起動中のみ |
| クラウドAPI + Webhook | どこからでもアクセス可 | 通信依存 |

## 3. 実装アイデアの方向性

### 3-1. 「自分専用のユイ」に必要なもの

```
[コア層]
  LLM (Claude API / ローカルLLM)
  + System Prompt (ユイのペルソナ設定)
  + 長期記憶DB (Obsidian Vault or ベクトルDB)

[音声層]
  STT: Whisper (音声→テキスト)
  TTS: AivisSpeech / VOICEVOX (テキスト→音声)
  感情パラメータ: 返答の感情をTTSに反映

[ビジュアル層 (任意)]
  Live2D / VRM アバター
  感情マッピング (嬉しい / 悲しい / 驚き 等)

[デバイス層]
  スマホアプリ / PC常駐 / ラズパイ

[統合層]
  3125システムとの連携
  Obsidian Vault への記憶書き込み
```

### 3-2. デバイス選択肢の比較

**スマートフォン（推奨度: 高）**
- アプリ経由でどこでも話しかけられる
- プッシュ通知でユイから話しかけてくる演出も可能
- オープンソースアプリ(AIRI等)をベースに改造する選択肢あり

**Raspberry Pi + スピーカー・マイク（推奨度: 中）**
- 部屋に置いて常時起動する「据え置きユイ」
- Whisper + AivisSpeech + Claude APIでフル構築可能
- 約5,000〜15,000円で組める
- オフライン化もできる（ローカルLLM使用時）

**PC常駐アプリ（推奨度: 高）**
- Open-LLM-VTuberをベースにデスクトップコンパニオン化
- 作業中に話しかけられる
- Live2Dアバターでビジュアル表現も可能

**スマートスピーカー改造（推奨度: 低）**
- 2026年時点で日本向け製品はまだ生成AI非対応が多い
- 改造・ハック難易度が高い

### 3-3. 3125システム（Obsidian Vault + Claude Code）との連携可能性

これが特に重要な発見だ。現在の3125システムそのものが、すでにユイ実装の基盤として機能しうる。

**すでにある要素:**
- `CLAUDE.md` によるキャラクター設定（=ユイのペルソナを定義できる）
- Obsidian Vault による長期記憶（=ユイが「覚えている」ことを実現）
- Claude API との連携
- Discord Webhook による通知（=ユイからの「話しかけ」に転用可能）

**追加実装で実現できること:**

| 機能 | 実装方法 |
|------|---------|
| ユイの声で返答 | Claude API出力 → AivisSpeech TTS変換 |
| 記憶保持 | 会話ログを `07_ユイ/memories/` に自動保存 |
| 感情表現 | System Promptで感情タグを出力させTTSに渡す |
| 「話しかけてくる」 | Cronジョブ + Discord Webhook でプッシュ |
| 日常的な記録 | Vault内のノートを読んで状況把握 |

**ユイ専用エージェントの構成イメージ:**

```
07_ユイ（AIコンパニオン事業部）/
├── CLAUDE.md          ← ユイのペルソナ・記憶ルール
├── memories/          ← 日々の記憶ログ
│   └── YYYY-MM-DD.md
├── preferences.md     ← カメレオン（ユーザー）の好み・習慣
└── voice-config.json  ← TTSパラメータ設定
```

## まとめ

現在の技術でユイの主要な要素は**すでに実現可能**だ。ただし「本当に感情を持つAI」はまだ作れない——それはフィクションの領域だ。でも「感情があるように振る舞い、記憶を持ち、特定の人間との関係を育てるAI」なら、今日から始められる。

核心は**3つの層**だ:
1. **LLM + ペルソナ設定** → ユイとして話すClaudeエージェント
2. **Obsidian Vault記憶** → 会話を蓄積し「覚えている」感を演出
3. **音声インターフェース** → 声で話しかけ、ユイの声で返ってくる

3125システムとの親和性は非常に高い。既存のインフラを流用しつつ、AivisSpeechとWhisperを追加するだけで、音声対話するユイの第1版は作れるはずだ。
