# デザインを学習して、反映できるClaudeのSkillを作る

---

## ① 元のアイデア整理

**元の着想:**
「デザインを学習して、反映できるClaudeのSkillを作る」

Claude Code のカスタムスキル（`.claude/commands/` や `CLAUDE.md` への知識注入）を活用し、特定のデザイン知識・スタイルガイドを学習させる。それをWeb制作・AIシステム開発・LPデザイン等の実務に即時反映できる仕組みを構築するというアイデア。

**コアコンセプト:**
- Claude Code にデザイン知識（UIルール・ブランドガイドライン・コンポーネント設計）を埋め込む
- プロジェクトごとに専用のデザインスキルを持たせることで、指示なしにデザイン一貫性を担保する
- オーナー（カメレオン）が毎回デザインルールを説明する手間をなくし、生産性を高める

---

## ② 課題・背景

### 現状のデザイン作業における課題

| 課題 | 詳細 |
|------|------|
| コンテキスト再説明コスト | 新しいチャット/タスクのたびに「このサイトはこういうデザインです」と説明し直す必要がある |
| デザイン一貫性の担保困難 | Claude に都度生成させると、微妙にスタイルがブレる（色・余白・フォントスタイル等） |
| ブランドガイドラインの未活用 | 会社・クライアントのブランドガイドラインを Claude が知らないまま作業してしまう |
| コンポーネント再生成の重複 | 同じようなUIコンポーネントを何度も一から生成させている |
| LP/Webの品質ばらつき | 担当者・プロジェクトによってデザインクオリティが均一にならない |

### AIでできること（Claude Code スキルの可能性）

- `CLAUDE.md` や `.claude/commands/` に設計情報・デザインシステムを記述しておけば、Claude Code が毎回それを参照して作業できる
- プロジェクトルートに置くだけで、そのプロジェクト専用のデザイン知識を自動ロードできる
- カスタムスラッシュコマンド（例: `/design-component`）でコンポーネント生成を標準化できる

---

## ③ 展開案

### 案A: UIデザインルール学習スキル
**概要:** 渡邊カンパニー共通のUIデザインルール（色・タイポグラフィ・余白・ボタン仕様等）を `CLAUDE.md` に記述し、全Web制作プロジェクトで共有する。

- **メリット:** 一度書けばすべてのプロジェクトに適用できる。デザインの最低品質が底上げされる。
- **懸念:** プロジェクトによってデザインが異なる場合、共通ルールとの衝突が起きる。
- **収益モデル:** 社内品質向上 → 納品速度アップ → 案件受注数増加。

---

### 案B: ブランドガイドライン反映スキル（クライアント別）
**概要:** クライアントごとに `.claude/` ディレクトリを作成し、そのクライアントのブランドガイドライン（ロゴルール・カラーパレット・フォント・トーン&マナー）を注入する。

- **メリット:** クライアントのブランドを忠実に再現できる。説明コストゼロ。
- **懸念:** クライアントごとにガイドラインの整備が必要。初期コストがかかる。
- **収益モデル:** 高品質なWeb制作・LP制作の差別化 → 単価アップ。

---

### 案C: コンポーネント生成スキル（スラッシュコマンド型）
**概要:** `/design-hero`・`/design-cta`・`/design-card` などのカスタムコマンドを作り、呼び出すだけで標準化されたコンポーネントHTMLを生成する。

- **メリット:** 繰り返し作業を一瞬で完了できる。新人でも一定品質を担保できる。
- **懸念:** コマンド定義の作成・メンテナンスコストがかかる。
- **収益モデル:** 制作工数削減 → 利益率向上。外部向けに「AIデザインキット」として販売も可。

---

### 案D: デザインレビュースキル（既存デザインの評価・改善提案）
**概要:** 既存のHTML/CSSを渡すと、定義済みのデザインルールと照合して改善点を指摘・修正するスキル。`/design-review` コマンドで起動。

- **メリット:** コードレビューと同様にデザインレビューを自動化できる。品質管理ツールとして機能する。
- **懸念:** デザインルールが明文化されていないと比較基準が曖昧になる。
- **収益モデル:** 社内品質管理の効率化。顧客向けサービスとして「AIデザイン診断」として展開も可。

---

### 案E: デザイン学習フロー（スクリーンショット→ルール抽出→スキル生成）
**概要:** 既存の良質なデザイン（自社・競合・参考サイト）のスクリーンショットをClaudeに読み込ませ、デザインルールを自動抽出して `CLAUDE.md` の形式に変換するパイプラインを作る。

- **メリット:** デザインルールをゼロから書かなくていい。既存の資産を活用できる。
- **懸念:** Claude の画像解析精度に依存する。抽出精度は完璧ではない。
- **収益モデル:** AI導入支援サービスの一環として提供。「デザインAI化コンサル」として販売可能。

---

## ④ おすすめ案と実現可能性

### 推奨: 案C（コンポーネント生成スキル）＋ 案B（ブランドガイドライン）の組み合わせ

**理由:**
- 案C はすぐに実装でき、毎日の業務に即効性がある。Claude Code のカスタムコマンドは `.claude/commands/*.md` に Markdown を置くだけで動作する。実現可能性は高い。
- 案B はクライアント案件での品質向上と差別化に直結する。ブランドガイドラインを `CLAUDE.md` に記述する形式は Claude Code が正式にサポートしている。

**Claude Code での実装可能範囲:**

| 機能 | 実現可否 | 実装方法 |
|------|---------|---------|
| デザインルールの永続化 | 可 | プロジェクトの `CLAUDE.md` に記述 |
| コンポーネント生成コマンド | 可 | `.claude/commands/` にスラッシュコマンド定義 |
| クライアント別ブランド反映 | 可 | クライアントフォルダの `CLAUDE.md` に記述 |
| 画像からルール抽出（案E） | 可（精度に注意） | マルチモーダルで画像を渡してルール抽出 |
| デザインレビュー自動化 | 可 | スラッシュコマンド＋ルールファイル参照 |

## ⑤ 次のアクション候補

1. **【今すぐできる】** 渡邊カンパニー共通のUIデザインルールを言語化し、`.claude/DESIGN.md` として整備する
2. **【試作】** LP制作プロジェクト1件で案Cを試験実装。`/design-hero`・`/design-cta` コマンドを作ってみる
3. **【調査】** 現行の優良LP・制作物からデザインルールを抽出（案Eのパイプライン試作）
4. **【中期】** クライアント別ブランドガイドラインの整備開始。まず主要2〜3クライアントから
5. **【展開】** 社内整備が完了したら「AIデザインキット」として外部サービス化を検討

## 🔍 ブリーフィング（CEOへ）

### 気づいたこと・注目点

- Claude Code の `CLAUDE.md` / `.claude/commands/` の仕組みは、デザイン知識の永続化に非常に相性が良い。技術的障壁は低く、すぐに着手できる。
- 案C（コンポーネント生成コマンド）は工数削減効果が大きく、LP制作・Web制作の利益率改善に直結する可能性がある。
- 案E（スクリーンショット→ルール抽出）は AI 導入支援サービスとして外販できるポテンシャルがある。渡邊カンパニーの強みを活かせる領域だ。

### 他部署への推奨アクション（任意）

- 【開発部へ】案C・案Dのスラッシュコマンドの試作実装を検討してほしい
- 【営業部へ】「AIデザインキット」「AIデザイン診断」サービスとしての外販可能性を市場調査してほしい
- 【リサーチ部へ】競合他社が Claude Code のカスタムスキルをデザイン業務に活用している事例を調査してほしい
