## 案件オープンチャット処理ルール

### 概要
案件専用のLINEオープンチャットのトーク履歴 `.txt` を解析し、案件情報を構造化して一覧管理する。

### 投入口
- `case-inbox/` に LINE「トーク履歴を送信」で書き出した `.txt` を手動で置く
- `/company` 起動時に自動で処理される

### 処理フロー
1. `case-inbox/` 内の `.txt` を全て読み込む
2. Claude で解析し、案件ごとに構造化データを抽出する
3. `cases/YYYY-MM-DD-案件ログ.md` に日別ログとして保存（受信トレイ経由）
4. 処理済み `.txt` を `case-inbox/_archive/` に移動
5. `cases/` 配下の直近3ヶ月分のログを全て読み込む
6. 全案件を統合・重複排除し `cases/_案件マスター.md` を**上書き生成**

### 案件抽出ルール
トーク内容から以下の項目を抽出する。情報がない項目は「記載なし」とする。

| 項目 | 説明 |
|------|------|
| 案件名 | 案件の識別名（ブランド×業務内容×店舗で構成） |
| クライアント | 発注元・元請け企業名 |
| 業務内容 | キャッチャー、クローザー、常勤、コール、イベント等 |
| ブランド | au, SB, YM, 楽天, HUAWEI, 光回線 等 |
| 単価 | 日当 or 月額（交通費込/別も明記） |
| エリア | 勤務地・店舗名 |
| 期間 | 開始日〜終了日、長期、単発 等 |
| 募集人数 | 何名募集か |
| 未経験 | 可 / 不可 / 微経験可 |
| 外国人 | 可 / 不可 / 要確認 / 記載なし |
| 投稿者 | オープンチャットでの投稿者名 |
| 投稿日 | 案件が投稿された日付 |
| 備考 | 面談有無、条件の補足、特記事項 |

## 議事録の振り分けルール

`type: minutes` のキューは内容に応じて保存先を切り替える:

| 議事録の種類 | target_folder | 判定基準 |
|------------|---------------|---------|
| 役員トーク（社内役員間の会話） | `04_3125アイデア保管事業部（アイゼン）/役員トーク` | 参加者が社内役員のみ、経営方針・戦略・内部の話題 |
| 商談・外部打ち合わせ | `04_3125アイデア保管事業部（アイゼン）/営業情報` | クライアント・外部パートナーとの会話、提案・案件の話 |

**判定に迷った場合:**
- 「役員定例」「経営会議」「社内MTG」→ 役員トーク
- 「商談」「打ち合わせ」「提案」「クライアント名あり」→ 営業情報
- 不明な場合 → 営業情報（デフォルト）

## 役員トーク履歴について

`exec-inbox/` への `.txt` 投入と `役員トーク/` への保存は **フリーレン（秘書）が担当**。
アイゼンはこの処理に関与しない。
ただし `type: minutes` で役員トークに該当する議事録が来た場合は、アイゼンが `役員トーク/` に保存する。
