# シニア向け広告ブロックアプリ「まもるくん」開発仕様書

---

## 1. 要件定義

### 1-1. 目的・背景

#### 課題の本質

現在、日本のシニア層（65歳以上）のスマートフォン利用者において、悪質な広告アプリ（アドウェア）による端末の機能不全が深刻化している。具体的には以下の事象が確認されている。

- **広告の無限ループ**: アドウェアが全画面広告を表示し続け、閉じるたびに別の広告が起動するループ状態が発生する
- **自己再起動機構**: アドウェアがバックグラウンド常駐・自動再起動の仕組みを悪用し、端末を再起動しても除去されない
- **通知権限の悪用**: インストール時に取得した通知権限を使い、ロック画面・通知バーへの広告挿入を行う
- **全画面広告偽装**: システム警告・セキュリティアラートに見せかけた全画面広告でシニアを誘導・課金させる
- **非公式ソースからのインストール**: Google Play外からのAPKサイドロードにより、マルウェア一歩手前のアプリが混入する

#### 代理店・スマホショップが抱える問題

スマホショップに持ち込まれるシニア客のトラブルの相当数が上記に起因するが、現場は以下の理由で対応できていない。

- 原因アプリの特定に時間がかかる（経験と勘に頼る属人的作業）
- 「対応外」として対応を断らざるをえない（工数・スキルの問題）
- 解決できないまま帰宅させた顧客が2度と来店しなくなる（顧客離脱）
- 店員が説明しても「何を削除すればいいか」をシニア本人が理解できない

#### 本プロダクトが解決すること

本アプリは、**スマートフォン内にインストールされている全アプリを自動スキャンし、問題度スコアを算出・可視化する**ことで、以下を実現する。

- 店頭でのトラブル診断時間を大幅短縮（属人的スキル不要）
- シニア本人でも理解できるUI（平易な言葉・大文字・高コントラスト）で自力解決を補助
- 子ども世代が遠隔から状況を把握し、適切なサポートを行える
- 代理店・スマホショップにとっての差別化サービスとしてのライセンス提供

### 1-2. 対象ユーザー（3者構造）

| ユーザー | 役割 | 主な使用シーン |
|----------|------|----------------|
| **シニア本人**（65歳以上） | エンドユーザー | 自宅でアプリを起動し、スキャンを実行する。結果を見て削除操作を行う |
| **子ども世代**（40〜60代）| 遠隔サポーター | 親のスキャン結果を通知受信・遠隔確認。削除指示をアプリ経由で送る |

### 1-3. 機能要件

#### コア機能（MVP対象）

| 機能ID | 機能名 | 概要 |
|--------|--------|------|
| F-01 | インストール済みアプリスキャン | `PackageManager` APIで端末内全アプリを取得し、属性情報を収集する |
| F-02 | 問題度スコアリング | 取得した属性をルールベースで評価し、0〜100のスコアと「危険/要注意/安全」の3段階判定を行う |
| F-03 | スキャン結果表示 | 問題度の高い順にアプリリストを表示。アプリ名・問題の理由・推奨アクションを平易な言葉で表示する |
| F-04 | 削除ガイド | 対象アプリの削除手順をステップ表示（Androidのシステム設定へ誘導）。自動削除は行わない |
| F-05 | 通知権限一括確認 | 不審なアプリへの通知権限付与状況を一覧表示し、無効化操作をシステム設定へ誘導する |

#### 拡張機能（フェーズ2以降）

| 機能ID | 機能名 | 対象フェーズ |
|--------|--------|-------------|
| F-06 | 家族報告機能 | スキャン結果を家族（子ども世代）にプッシュ通知・メール送信する | フェーズ2 |
| F-07 | 定期自動スキャン | 週次・月次でバックグラウンドスキャンを実行し、新規問題アプリを検知する | フェーズ2 |
| F-08 | VirusTotal API連携 | アプリのパッケージ名・ハッシュをVirusTotal APIで照合し、既知マルウェア判定を強化する | フェーズ2〜3 |
| F-09 | 遠隔サポート画面共有 | 子ども世代がリモートで画面を確認し、操作ガイドをリアルタイムで送る | フェーズ3 |
| F-10 | 店舗向けレポート出力 | B2B向けにPDFレポートを生成。来店客への説明資料として使用できる | フェーズ2 |
| F-11 | クラウド問題アプリDBの更新 | サーバーサイドで問題アプリリストを更新し、アプリ側に配信する | フェーズ2〜3 |

### 2-2. データモデル

#### AppInfo（アプリ情報エンティティ）

```kotlin
data class AppInfo(
    val packageName: String,          // パッケージ名（一意識別子）
    val appName: String,              // 表示名
    val installSource: InstallSource, // インストール元 (PLAY_STORE / SIDE_LOAD / SYSTEM / UNKNOWN)
    val installDate: Long,            // インストール日時（Unix timestamp）
    val hasNotificationPermission: Boolean, // 通知権限の有無
    val hasBootReceiver: Boolean,     // 自動起動レシーバーの有無
    val hasAdminPermission: Boolean,  // デバイス管理者権限の有無
    val targetSdkVersion: Int,        // ターゲットSDKバージョン
    val requestedPermissions: List<String>, // 要求権限リスト
    val isSystemApp: Boolean,         // システムアプリかどうか
)

enum class InstallSource {
    PLAY_STORE, SIDE_LOAD, SYSTEM, UNKNOWN
}
```

#### ScoringRule（スコアリングルール）

```kotlin
data class ScoringRule(
    val ruleId: String,           // ルールID（例: "SIDELOAD_INSTALL"）
    val description: String,      // 判定理由（日本語・平易表現）
    val scoreWeight: Int,         // 加算スコア（0〜30）
    val severity: Severity,       // 重大度 (CRITICAL / WARNING / INFO)
)

enum class Severity {
    CRITICAL,   // 危険
    WARNING,    // 要注意
    INFO        // 参考情報
}
```

#### ScanResult（スキャン結果）

```kotlin
data class ScanResult(
    val scanId: String,           // スキャンID（UUID）
    val scannedAt: Long,          // スキャン日時
    val totalApps: Int,           // スキャンしたアプリ総数
    val results: List<AppScanResult>, // 個別アプリ結果リスト
)

data class AppScanResult(
    val appInfo: AppInfo,
    val totalScore: Int,          // 問題度スコア（0〜100）
    val judgment: Judgment,       // 判定 (DANGER / CAUTION / SAFE)
    val triggeredRules: List<ScoringRule>, // 該当したルールリスト
    val userFriendlyReason: String,   // 平易な言葉での説明
    val recommendedAction: String,    // 推奨アクション（平易な言葉）
)

enum class Judgment {
    DANGER,   // 危険（スコア60以上）
    CAUTION,  // 要注意（スコア30〜59）
    SAFE,     // 安全（スコア0〜29）
}
```

#### スコアリングルール定義（初期ルールベース）

| ルールID | 条件 | 加算スコア | 重大度 | 表示テキスト（平易） |
|----------|------|-----------|--------|---------------------|
| SIDELOAD_INSTALL | インストール元がPlayStore以外 | +30 | CRITICAL | 「安全でない場所からインストールされています」 |
| DEVICE_ADMIN | デバイス管理者権限を持つ（非システムアプリ） | +25 | CRITICAL | 「スマホの管理権限を持っています（危険）」 |
| BOOT_RECEIVER + NOTIFICATION | 自動起動権限と通知権限を両方持つ | +20 | WARNING | 「勝手に起動して通知を送る仕組みがあります」 |
| OLD_TARGET_SDK | targetSdkVersion < 26（Android 8未満対応） | +15 | WARNING | 「古いアプリです。セキュリティに問題がある可能性があります」 |
| DANGEROUS_PERMISSIONS | READ_CONTACTS / SEND_SMS 等の高リスク権限 | +10〜15 | WARNING | 「電話帳や SMS を読み取る権限があります」 |
| UNKNOWN_SOURCE | インストール元が UNKNOWN | +20 | WARNING | 「どこからインストールされたかわかりません」 |

### 2-4. 技術スタック推奨

| 区分 | 推奨技術 | 理由 |
|------|---------|------|
| **フロントエンド** | Flutter（Dart） | iOS展開への将来対応。UI統一管理が容易。シニアUI部品の再利用性が高い |
| **代替フロントエンド** | Kotlin（Android Native） | Flutter不可の場合。PackageManager APIへのアクセスが最も素直 |
| **状態管理** | Riverpod（Flutter）/ ViewModel（Kotlin） | スキャン状態・結果の管理に適している |
| **ローカルDB** | SQLite / Room（Kotlin）/ sqflite（Flutter） | スキャン履歴のローカル永続化 |
| **プッシュ通知** | Firebase Cloud Messaging（フェーズ2） | 家族への通知配信 |
| **バックエンド** | Node.js + Vercel / Firebase Functions（フェーズ2） | 軽量・低コスト。MVP後の迅速な追加開発 |
| **外部API** | VirusTotal API v3（フェーズ2〜3） | 既知マルウェア照合 |
| **認証** | Firebase Authentication（フェーズ2） | 家族連携・デバイス紐付け |

#### MVPにおける技術選定の判断基準

- PackageManager APIは Flutter の`device_apps`パッケージ または Kotlin MethodChannel経由で取得可能
- Flutter を選ぶ場合、`device_apps` / `installed_apps` パッケージを活用する
- Kotlin を選ぶ場合、`PackageManager.getInstalledPackages(PackageManager.GET_PERMISSIONS)` を直接呼ぶ
- **シニアUIXの観点からはどちらでも実現可能だが、Kotlinの方がAndroidシステム連携の実装難易度が低い**

## 3. Claude Code MVP用プロンプト

以下のプロンプトをそのままClaude Codeに渡すことで、MVP実装を開始できる。

---

```
# タスク: Androidアプリ「まもるくん」MVPの実装

## 概要
シニア（65歳以上）向けのAndroidアプリを実装してください。
端末内のインストール済みアプリをスキャンし、怪しいアプリを「危険/要注意/安全」の3段階で判定・表示するアプリです。
スマホショップ店員が来店客の端末診断に使うB2Bツールとして機能することも想定しています。

## 使用技術
- **言語**: Kotlin
- **最小対応バージョン**: Android 9（API Level 28）
- **アーキテクチャ**: MVVM（ViewModel + LiveData / StateFlow）
- **依存関係**: 外部ライブラリは最小限（Room, Coroutines のみ許可）

## 実装する画面と機能

### 画面1: メイン画面（MainActivity）
- 画面中央に大きな「スキャンする」ボタン（最小横幅: 画面幅の80%）
- フォントサイズは全画面で最小18sp
- 前回スキャン日時と検出問題数を表示（初回はグレーアウト）
- 「通知の確認」ボタン → 通知権限一覧画面へ遷移
- 背景白・文字黒のシンプル高コントラストデザイン

### 画面2: スキャン中画面（ScanningFragment）
- 水平プログレスバーでスキャン進捗を表示
- 「スキャンしています...」テキスト（20sp）
- バックグラウンドで PackageManager.getInstalledPackages() を実行（Coroutines / IO Dispatcher使用）
- スキャン完了後、自動でスキャン結果画面に遷移

### 画面3: スキャン結果画面（ScanResultFragment）
- RecyclerView で問題アプリリストを表示
- セクション分け: 「⚠️ 危険なアプリ」「⚡ 気になるアプリ」「✅ 問題なし（折りたたみ）」
- 各アプリ行にアプリアイコン・アプリ名・危険度（★1〜5）を表示
- タップでアプリ詳細・削除ガイド画面に遷移

### 画面4: アプリ詳細・削除ガイド画面（AppDetailFragment）
- アプリ名・問題の理由（平易な日本語）を表示
- 「削除の画面を開く」ボタン → 以下のIntentでAndroid設定画面を開く
  ```kotlin
  Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS).apply {
      data = Uri.parse("package:${appInfo.packageName}")
  }
  ```
- 削除手順を番号付きステップで表示（例: 「1. 「アンインストール」をタップ」）

### スコアリングルール（全ルールを実装すること）

以下のルールを順番に評価し、スコアを合算すること。

```kotlin
// ルール1: サイドロード検出（+30点）
// インストール元が "com.android.vending"（Google Play）以外の場合
val installer = packageManager.getInstallerPackageName(pkg.packageName)
if (installer != "com.android.vending" && !isSystemApp) score += 30

// ルール2: デバイス管理者権限（+25点）
// DevicePolicyManager.getActiveAdmins() に含まれるか確認
// システムアプリは除外すること

// ルール3: BOOT_COMPLETED + 通知権限の両方保持（+20点）
val hasBootReceiver = pkg.receivers?.any { 
    it.permission == "android.permission.RECEIVE_BOOT_COMPLETED" 
} ?: false
val hasNotification = NotificationManagerCompat.from(context)
    .areNotificationsEnabled() // ※アプリ単位の確認はAPI 26以上で NotificationChannel 経由

// ルール4: targetSdkVersion が 26 未満（+15点）
if (pkg.applicationInfo.targetSdkVersion < 26) score += 15

// ルール5: 高リスク権限の保持（+10〜15点）
val dangerousPermissions = listOf(
    "android.permission.READ_CONTACTS",      // +10
    "android.permission.READ_CALL_LOG",      // +10
    "android.permission.SEND_SMS",           // +15
    "android.permission.RECEIVE_SMS",        // +15
    "android.permission.READ_SMS",           // +15
)
// 該当する権限ごとに加算（上限30点）

// ルール6: インストール元 UNKNOWN（+20点）
if (installer == null && !isSystemApp) score += 20
```

### 判定区分
- スコア 60以上 → DANGER（危険）
- スコア 30〜59 → CAUTION（要注意）
- スコア 0〜29 → SAFE（安全）

### システムアプリの扱い
- `ApplicationInfo.FLAG_SYSTEM` フラグを持つアプリはスキャン結果から除外する
- または「システムアプリ」として別カテゴリに分類し、デフォルト非表示にする
