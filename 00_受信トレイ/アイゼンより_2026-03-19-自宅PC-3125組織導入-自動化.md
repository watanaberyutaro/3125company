# 自宅PC（Windows）に3125組織を導入・自動化

**作成日**: 2026-03-19
**担当**: アイゼン（04_3125アイデア保管事業部）

---

## 1. 元のアイデア整理

- 現在、MacBookでObsidian Vault + Claude Code + 3125組織システムを運用中
- 自宅のWindows PCにも同じ組織システムを導入し、自動化を実現したい
- MacroDroid（Android自動化）の確定仕様が既にあり、モバイルからの自動入力パイプラインは構築中
- Windows側でも同等の自動化（ファイル監視・トリガー実行・Claude Code連携）を実現する構想

---

## 2. 課題・背景

| 課題 | 内容 |
|------|------|
| Vault同期 | MacとWindowsでObsidian Vaultを同期する必要がある（iCloud前提の現構成との整合性） |
| Claude Code対応 | Claude CodeがWindows上でどこまで動作するか（WSL経由 or ネイティブ） |
| 自動化ツールの差異 | Macのlaunchd/Automatorに相当する仕組みをWindowsで再現する必要がある |
| 環境の一貫性 | Mac/Windows両方で同一の.claude/commandsやCLAUDE.mdが動作する保証 |
| コスト | 追加のサブスクリプションやライセンスを最小限に抑えたい |

---

## 3. 展開案

### 案A: WSL2 + Claude Code ネイティブ構成

**仕組み:**
- Windows上にWSL2（Ubuntu）を導入
- WSL2内にClaude Codeをインストールし、Mac版と同一のコマンド体系で運用
- Obsidian VaultはiCloud for Windowsまたは別の同期手段（Syncthing等）でMacと同期
- WSL2のcronやsystemdタイマーでファイル監視・定期実行を自動化

**メリット:**
- Macとほぼ同一の環境が再現できる（bash, node, Claude Code全て動く）
- .claude/commands/やCLAUDE.mdがそのまま流用可能
- WSL2のファイルシステムからWindowsフォルダにアクセス可能（/mnt/c/）

**懸念:**
- iCloud for WindowsはObsidian Vaultの同期で不安定な報告あり
- WSL2のメモリ使用量が大きい（.wslconfigで制限可能）
- WSL2内からWindows側の通知を出すには追加の工夫が必要

**コスト:** 無料（WSL2は標準機能）

---

### 案B: PowerShell + Task Scheduler 構成（WSLなし）

**仕組み:**
- Claude CodeをWindows版Node.js上で直接実行
- PowerShellスクリプトでファイル監視（FileSystemWatcher）・トリガー実行
- Windowsタスクスケジューラで定期実行（起動時・ログイン時・一定間隔）
- Vaultの同期はSyncthingまたはOneDrive経由

**メリット:**
- WSL不要でリソース消費が少ない
- Windowsネイティブの通知・自動化がそのまま使える
- PowerShellはWindows標準で追加インストール不要

**懸念:**
- bashスクリプト（.claude/commands/）はPowerShellに書き換えが必要
- Macとの設定ファイル互換性の維持コストが高い
- Claude Codeのbashコマンド実行がcmd.exe/PowerShell経由になり挙動差の可能性

**コスト:** 無料

---

### 案C: WSL2 + Syncthing + AutoHotkey ハイブリッド構成（推奨）

**仕組み:**
- WSL2内でClaude Code・bash環境を再現（Mac互換）
- SyncthingでMac-Windows間のVault同期（iCloudを介さない直接P2P同期）
- AutoHotkey（Windows側）でホットキー・GUI操作の自動化を追加
- Power Automateで定型業務（メール処理・ファイル整理等）を補助

**メリット:**
- SyncthingはP2P同期で無料・高速・iCloudの不安定さを回避
- WSL2でMac環境をほぼ完全再現しつつ、AHKでWindows固有の自動化も可能
- MacroDroid（Android）→ Syncthing → Windows/Mac の3デバイス同期も実現可能

**懸念:**
- Syncthing常駐によるバッテリー・リソース消費（デスクトップPCなら問題なし）
- 初期セットアップに時間がかかる（Syncthing + WSL2 + AHK の3つ）
- コンフリクト解消ルールを事前に決める必要あり

**コスト:** 無料（全て無料ソフト）

---

### 案D: Docker + Claude Code コンテナ構成

**仕組み:**
- Docker Desktop for Windowsを導入
- Claude Code実行環境をDockerコンテナ化し、Mac/Windows共通で運用
- Vaultはホストマシンからボリュームマウント
- docker-composeで環境定義を共有

**メリット:**
- Mac/Windows完全同一の実行環境を保証
- Dockerfileで環境構築を再現可能（壊れても即復元）
- 将来的にVPSやクラウドへの移植も容易

**懸念:**
- Docker Desktopのライセンス（個人利用は無料）
- ファイルI/Oが遅い（ボリュームマウントのオーバーヘッド）
- Obsidianとの同時編集でロック競合の可能性

**コスト:** 無料（個人利用）

---

### 案E: リモートアクセス構成（MacをWindows PCから操作）

**仕組み:**
- MacBookを常時起動しておき、Windows PCからTailscale + SSH/VNCでリモート操作
- Claude Codeの実行はすべてMac側で行い、Windows PCは端末として使うのみ
- Vault自体の同期は不要（Mac上の1インスタンスのみ）

**メリット:**
- 同期・環境差異の問題が根本的に発生しない
- セットアップが最もシンプル
- MacBookが動いている限り、どこからでも操作可能

**懸念:**
- MacBookが常時起動前提（電気代・ハード寿命）
- ネットワーク遅延でリアルタイム操作がストレスになる可能性
- Windows PC側で独立した自動化処理は実行できない

**コスト:** 無料（Tailscaleは個人利用無料）

---

## 4. おすすめ案

**案C: WSL2 + Syncthing + AutoHotkey ハイブリッド構成を推奨する。**

理由:
- WSL2でMac環境をほぼ完全に再現できるため、.claude/commands/やCLAUDE.mdの書き換えが不要
- SyncthingはiCloudより同期が安定しており、Android（MacroDroid）を含む3デバイス統合に最適
- AutoHotKeyでWindows固有の操作自動化（ホットキーでClaude Code起動、クリップボード監視等）を追加でき、Mac以上の自動化も可能
- 全て無料ソフトで構成可能
- 自宅PCはデスクトップなのでSyncthingの常駐リソースも問題にならない

**構成イメージ:**
```
[MacBook] ←─Syncthing─→ [Windows PC (WSL2)]
    ↑                          ↑
    └──── Syncthing ────→ [Android (MacroDroid)]
                               │
                          通知キャプチャ → Webhook → Vault保存
```

## ブリーフィング（CEOへ）

### 気づいたこと・注目点
- iCloud同期はWindowsとの相性が悪いという報告が多い。Syncthingに切り替えることでMac側もiCloud依存から脱却でき、長期的にリスクが下がる
- WSL2であればMacの.claude/commandsやbashスクリプトがそのまま動くため、「2つの環境を別々にメンテする」コストがほぼゼロになる
- Android（MacroDroid）との3デバイス同期まで視野に入れると、SyncthingのP2P構成が最も筋がいい
- 全て無料ソフトで構成可能。追加コストなし
