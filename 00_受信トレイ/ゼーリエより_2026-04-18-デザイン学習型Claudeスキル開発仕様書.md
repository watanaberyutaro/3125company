# デザイン学習型 Claude Code スキル 開発仕様書

---

## 1. 要件定義

### 1-1. 目的・背景

渡邊カンパニーはWeb制作を事業の柱のひとつとする。しかし、制作のたびに「どんなデザインにするか」をゼロから検討するのは非効率であり、品質にもばらつきが生じる。

本スキルは、参照したい既存サイトのデザインをClaude Codeに「学習」させ、そのデザインDNA（色・タイポグラフィ・レイアウト・コンポーネントパターン等）を蓄積・参照できる仕組みを提供する。これにより、美しく一貫性のあるWeb制作を高速に実現することを目的とする。

### 1-2. ユーザーストーリー

#### `/design-learn [URL]` スキル

| # | ストーリー |
|---|-----------|
| 1 | 開発者として、URLを渡すだけでそのサイトのデザイン特性を自動抽出し、ライブラリに蓄積できる |
| 2 | 開発者として、複数のサイトを繰り返し学習させ、蓄積量を増やしていける |
| 3 | 開発者として、学習済みサイトの一覧と各サイトの要約を確認できる |
| 4 | 開発者として、既に学習済みのURLを再学習させた場合は上書き更新される |

#### `/design-apply [指示]` スキル

| # | ストーリー |
|---|-----------|
| 1 | 開発者として、蓄積されたデザインDNAを参照してHTMLとCSSを生成してもらえる |
| 2 | 開発者として、「AサイトのようなLP」「BサイトとCサイトを融合したスタイル」といった自由な指示が可能 |
| 3 | 開発者として、生成されたコードはそのままブラウザで動作するレベルのクオリティを期待できる |

### 1-3. 機能要件

| ID | 機能 | 説明 |
|----|------|------|
| F01 | デザイン抽出 | URLのHTMLを取得し、カラー・タイポ・レイアウト・余白・コンポーネント等を抽出する |
| F02 | ライブラリ蓄積 | 抽出したデザインDNAを `.claude/design-library.json` に追記保存する |
| F03 | 重複URL上書き | 同一URLを再学習した場合は既存エントリを上書きする |
| F04 | 蓄積一覧表示 | 学習済みサイトの一覧（URL・サイト名・登録日・特徴要約）をMarkdown形式で出力する |
| F05 | デザイン参照制作 | 蓄積されたデザインDNAを参照し、指示に応じたHTML+CSSを生成する |
| F06 | 複数サイト融合 | 「AとBのスタイルを組み合わせて」といった指示に対応する |

### 1-4. 非機能要件

| ID | 要件 |
|----|------|
| NF01 | 蓄積ファイルは `.claude/design-library.json`（JSON形式）とする |
| NF02 | JSON構造は複数サイト対応のオブジェクト配列とし、URLをキーとして管理する |
| NF03 | HTMLが取得できない場合（CORSエラー・認証必須・タイムアウト）は明示的にエラーを報告し処理を中断する |
| NF04 | 蓄積ファイルが存在しない場合は新規作成して処理を継続する |
| NF05 | スキルファイルは `.claude/commands/` 配下に配置し、Claude Code標準の `/コマンド名` 記法で呼び出せる |
| NF06 | 将来的なサイト削除・エクスポート・タグ付け機能の追加を想定した拡張可能な構造とする |

## 2. 詳細設計

### 2-1. スキルファイル構成

```
プロジェクトルート/
├── .claude/
│   ├── commands/
│   │   ├── design-learn.md     ← /design-learn スキル本体
│   │   └── design-apply.md     ← /design-apply スキル本体
│   └── design-library.json     ← デザインDNA蓄積ファイル（自動生成・追記）
```

#### 呼び出し方法

```
/design-learn https://example.com
/design-apply モダンなSaaSのLP、ヒーローセクションとCTA付き
/design-apply example.comのスタイルを参考にコーポレートサイトのトップを作れ
```

### 2-2. デザインDNA抽出ロジック

WebFetch でURLのHTMLを取得した後、以下の項目を抽出・推定する。Claude はHTMLのソースコードを解析し、インラインスタイル・`<style>` タグ・クラス名パターン・構造から判断する。

| カテゴリ | 抽出項目 | 説明 |
|---------|---------|------|
| **カラーパレット** | primary_color, secondary_color, accent_color, background_color, text_color | 主要色・背景色・テキスト色をHEX/RGB形式で |
| **タイポグラフィ** | font_family_heading, font_family_body, font_size_base, font_weight_heading, line_height | ヘッダー/ボディのフォント名・サイズ・ウェイト |
| **レイアウト** | layout_type, max_width, grid_system, breakpoints | グリッド型/カード型/全幅等の分類、最大幅px |
| **スペーシング** | section_padding, component_gap, border_radius | セクション余白・要素間隔・角丸の傾向 |
| **コンポーネントパターン** | nav_style, hero_style, cta_style, card_style, footer_style | ナビ・ヒーロー・CTA・カード・フッターの特徴 |
| **雰囲気・スタイル傾向** | design_mood, design_style, animation_tendency | ミニマル/ボールド/エレガント等の形容・アニメ有無 |
| **技術的特徴** | uses_glassmorphism, uses_gradient, uses_dark_mode, uses_custom_cursor | 特殊なUIトレンドの使用有無 |

### 2-3. `design-library.json` データ構造

蓄積ファイルは以下のスキーマに従う。

```json
{
  "version": "1.0",
  "sites": [
    {
      "url": "https://example.com",
      "site_name": "Example Corp",
      "learned_at": "2026-04-18T12:00:00+09:00",
      "summary": "モノクロを基調としたミニマルなSaaSサイト。大胆な余白と太いサンセリフ体が特徴。",
      "design_dna": {
        "colors": {
          "primary": "#000000",
          "secondary": "#ffffff",
          "accent": "#FF4500",
          "background": "#F8F8F8",
          "text": "#1A1A1A"
        },
        "typography": {
          "font_family_heading": "Inter, sans-serif",
          "font_family_body": "Inter, sans-serif",
          "font_size_base": "16px",
          "font_weight_heading": "700",
          "line_height": "1.6"
        },
        "layout": {
          "layout_type": "centered",
          "max_width": "1200px",
          "grid_system": "12-column",
          "breakpoints": ["768px", "1024px", "1280px"]
        },
        "spacing": {
          "section_padding": "80px 0",
          "component_gap": "24px",
          "border_radius": "8px"
        },
        "components": {
          "nav_style": "透明背景・左ロゴ・右CTAボタン・スティッキー",
          "hero_style": "全幅・中央揃え・大見出し+サブコピー+CTAボタン2つ",
          "cta_style": "塗りつぶしボタン・角丸8px・hover時に暗くなる",
          "card_style": "白背景・影あり・上画像+テキスト構造",
          "footer_style": "4カラム・濃いグレー背景・白テキスト"
        },
        "mood": {
          "design_mood": "professional",
          "design_style": "minimalist",
          "animation_tendency": "subtle fade-in on scroll"
        },
        "special_features": {
          "uses_glassmorphism": false,
          "uses_gradient": false,
          "uses_dark_mode": false,
          "uses_custom_cursor": false
        }
      }
    }
  ]
}
```

**URLの一意性管理**: `sites` 配列を検索し、同一URLが存在する場合は該当エントリを丸ごと置き換える。存在しない場合は末尾に追加する。

### 2-4. `/design-apply` が参照するプロンプト設計

1. `design-library.json` を読み込み、`sites` 配列全体を取得する
2. ユーザーの指示文からサイト名・URLのキーワードを検索し、参照対象を絞り込む（指定がなければ全サイトを参照）
3. 参照対象サイトの `design_dna` を構造化してシステムプロンプト的に展開する
4. ユーザー指示を実現するHTML+CSSを一枚のファイルとして生成する
5. 生成物はブラウザで直接開ける完結した `index.html` 形式とする

## 3. Claude Code MVP用プロンプト

### 3-1. `design-learn.md` 完全版

以下をそのまま `.claude/commands/design-learn.md` として保存すること。

---

```markdown
# design-learn

サイトのデザインを解析し、design-library.jsonに蓄積する。

## 引数

$ARGUMENTS にURLが渡される。

## 処理手順

以下の手順を順番に実行せよ。

### Step 1: 引数バリデーション

$ARGUMENTS が空の場合、または http:// か https:// で始まらない場合は以下を出力して処理を中断せよ:

```
エラー: URLを指定してください。
使用例: /design-learn https://example.com
```

### Step 2: HTMLの取得

WebFetch ツールを使って $ARGUMENTS のHTMLを取得せよ。プロンプトは以下とせよ:

「このページのHTMLソースコード全体を返してください。特にhead内のstyleタグ、bodyのクラス名・構造、カラーコード、フォント指定、グリッドやFlexboxの使用、CSSカスタムプロパティ（変数）に注目してください。」

取得に失敗した場合（エラーメッセージが返った場合）は以下を出力して処理を中断せよ:

```
エラー: URLへのアクセスに失敗しました。
- URLが正しいか確認してください
- 認証が必要なページはアクセスできません
- URL: [指定されたURL]
```

### Step 3: デザインDNAの抽出

取得したHTMLを解析し、以下の項目を推定・抽出せよ。HTMLに明示的な記述がない場合はビジュアルの雰囲気から推定し、推定であることを値のコメントには記載しなくてよい。

抽出項目:

**colors（カラーパレット）**
- primary: メインブランドカラー（HEX）
- secondary: サブカラー（HEX）
- accent: アクセントカラー・CTAボタン色（HEX）
- background: 背景色（HEX）
- text: 本文テキスト色（HEX）

**typography（タイポグラフィ）**
- font_family_heading: 見出しフォント名
- font_family_body: 本文フォント名
- font_size_base: 基本フォントサイズ（px）
- font_weight_heading: 見出しフォントウェイト（数値）
- line_height: 行間（数値）

**layout（レイアウト）**
- layout_type: "centered" / "full-width" / "asymmetric" / "card-grid" のいずれか
- max_width: コンテンツ最大幅（px）
- grid_system: "12-column" / "flex" / "css-grid" / "none"
- breakpoints: レスポンシブブレークポイント（配列、px単位）

**spacing（スペーシング）**
- section_padding: セクション上下余白（CSS形式）
- component_gap: コンポーネント間隔（px）
- border_radius: 角丸の基本値（px）

**components（コンポーネントパターン）**
- nav_style: ナビゲーションの特徴（1〜2文の日本語説明）
- hero_style: ヒーローセクションの特徴（1〜2文の日本語説明）
- cta_style: CTAボタンの特徴（1〜2文の日本語説明）
- card_style: カードコンポーネントの特徴（1〜2文の日本語説明）
- footer_style: フッターの特徴（1〜2文の日本語説明）

**mood（雰囲気）**
- design_mood: "professional" / "playful" / "elegant" / "bold" / "minimal" / "warm" から最も近いもの
- design_style: "minimalist" / "maximalist" / "flat" / "glassmorphism" / "neumorphism" / "brutalist" から最も近いもの
- animation_tendency: アニメーション・トランジションの傾向（1文）

**special_features（特殊要素）**
- uses_glassmorphism: true/false
- uses_gradient: true/false
- uses_dark_mode: true/false（デフォルトがダークモードの場合true）
- uses_custom_cursor: true/false

また、サイト名（title タグまたは og:site_name から取得）とサマリー（そのサイトのデザインを20〜40文字で表現する日本語の説明文）も生成せよ。

### Step 4: design-library.json の読み込みと更新

1. Read ツールで `.claude/design-library.json` を読み込め。ファイルが存在しない場合は以下の初期構造を使用せよ:

```json
{
  "version": "1.0",
  "sites": []
}
```

2. `sites` 配列を検索し、`url` フィールドが $ARGUMENTS と完全一致するエントリが存在するか確認せよ。

3. 以下の構造で新しいエントリオブジェクトを作成せよ:

```json
{
  "url": "[Step1のURL]",
  "site_name": "[Step3で取得したサイト名]",
  "learned_at": "[現在のISO8601日時]",
  "summary": "[Step3で生成したサマリー]",
  "design_dna": {
    "colors": { ... },
    "typography": { ... },
    "layout": { ... },
    "spacing": { ... },
    "components": { ... },
    "mood": { ... },
    "special_features": { ... }
  }
}
```

4. 同一URLのエントリが存在する場合は置き換え、存在しない場合は配列末尾に追加せよ。

5. Write ツールで `.claude/design-library.json` に書き込め。

### Step 5: 完了レポート出力

以下の形式で結果を出力せよ:

### 3-2. `design-apply.md` 完全版

以下をそのまま `.claude/commands/design-apply.md` として保存すること。

---

```markdown
# design-apply

蓄積されたデザインDNAを参照して、美しいWebページを制作する。

## 引数

$ARGUMENTS に制作指示が渡される。

## 処理手順

以下の手順を順番に実行せよ。

### Step 1: 引数バリデーション

$ARGUMENTS が空の場合は以下を出力して処理を中断せよ:

```
エラー: 制作指示を入力してください。
使用例: /design-apply モダンなSaaSのLP。ヒーローとCTA付き。
使用例: /design-apply example.comのスタイルを参考にコーポレートサイトのトップを作れ
```

### Step 2: design-library.json の読み込み

Read ツールで `.claude/design-library.json` を読み込め。

ファイルが存在しない、または `sites` 配列が空の場合は以下を出力して処理を中断せよ:

```
エラー: デザインライブラリが空です。
先に /design-learn [URL] でサイトを学習させてください。
```

### Step 3: 参照サイトの特定

$ARGUMENTS の文言を分析し、参照すべきサイトを以下のルールで特定せよ:

1. `$ARGUMENTS` 内にURLまたはサイト名のキーワードが含まれる場合、`design-library.json` の `url` または `site_name` を部分一致で検索し、該当サイトのみを参照対象とする
2. 複数のサイト名・URLが指定されている場合は、その全てを参照対象とする（融合モード）
3. 特定のサイト指定がない場合は、`sites` 配列の全エントリを参照対象とする

参照対象が決まったら以下を出力せよ:

```
参照するデザインライブラリ: [参照対象サイト名一覧]
```

### Step 4: デザインコンテキストの構築

参照対象サイトの `design_dna` を統合し、以下の形式でデザインコンテキストを構築せよ（内部処理として実行し、出力はしなくてよい）:

**単一サイト参照の場合**: そのサイトの `design_dna` をそのまま使用する。

**複数サイト融合の場合**:
- colors: 各サイトのプライマリカラーを順位付け、指示文のトーンに最も合うものを採用する
- typography: 最も洗練されていると判断できるフォント指定を採用する
- layout: 指示文の内容（LP/コーポレート/ブログ等）に最適なlayout_typeを採用する
- spacing / border_radius: 平均的な値を採用する
- components: 各サイトのコンポーネント説明を参照し、最良のパターンを選択する
- mood: 最もポジティブな評価が高い傾向（professional / elegant / bold）を優先する

**全サイト参照の場合**: 上記の複数サイト融合ロジックを全エントリに対して適用する。

### Step 5: HTML+CSSの生成

以下の制約に従い、$ARGUMENTS の指示を実現するHTMLを生成せよ。

**必須制約**:
- 完全に自己完結した1枚の `index.html` として生成する（外部CSSファイル不要・`<style>` タグ内にCSS全記述）
- Google Fonts は `<link>` タグで読み込んでよい（CDN依存は最小限）
- JavaScriptはインラインで記述してよい（必要な場合のみ）
- レスポンシブデザイン必須（モバイルファースト、ブレークポイントはStep4のコンテキストを使用）
- アクセシビリティ基本対応（alt属性・aria-label・適切な見出し構造）
- プレースホルダーテキストは日本語で記述する

**デザイン適用ルール**:
- Step4で構築したデザインコンテキストの `colors` をCSSカスタムプロパティ（`:root` 変数）として定義し、全体で使用する
- `typography` のフォントファミリー・サイズ・ウェイト・行間を忠実に再現する
- `layout` の `max_width` でコンテンツ幅を制御し、`grid_system` に応じてCSS GridまたはFlexboxを選択する
- `spacing` の `section_padding` ・`component_gap` ・`border_radius` を各要素に適用する
- `components` の各説明文を参考に、各セクションのHTML構造とスタイルを構築する
- `mood` の `design_style` に応じてグラスモーフィズム・グラデーション等の特殊表現を加える
- `animation_tendency` に記述があれば CSS transition / @keyframes で再現する

**生成するセクション（$ARGUMENTS の指示内容に応じて選択・追加）**:
- ナビゲーション（ロゴ + メニュー + CTAボタン）
- ヒーローセクション（大見出し + サブコピー + CTAボタン）
- フィーチャーセクション（3カラム以上のカード）
- 実績・数字セクション（カウンター的な見せ方）
- テスティモニアル（お客様の声）
- CTAセクション（コンバージョン誘導）
- フッター（リンク群 + コピーライト）

### Step 6: 生成完了レポート出力

HTMLの生成後、以下の形式でレポートを出力せよ:

```
✅ サイト制作完了

━━━━━━━━━━━━━━━━━━━━
制作物概要
━━━━━━━━━━━━━━━━━━━━
指示内容: [ARGUMENTS の要約]
参照サイト: [参照したサイト名]
採用カラー: Primary [primary] / Accent [accent]
採用フォント: [font_family_heading]
レイアウト: [layout_type] / 最大幅 [max_width]

━━━━━━━━━━━━━━━━━━━━

## ブリーフィング（CEOへ）

### 気づいたこと・注目点

- Claude Code スキルは引数を `$ARGUMENTS` で受け取るMarkdownファイルであるため、ロジックは「Claude への指示文」として記述する必要がある。実際のコードではなくプロンプトで処理フローを記述した。
- WebFetch で取得できるのはHTMLの可視テキスト+構造であり、外部CSSファイルの詳細を完全に取得できるとは限らない。そのため「推定」を許容する設計とし、抽出精度よりも動作の安定性を優先した。
- `design-library.json` を `.claude/` 配下に置く設計は、プロジェクト依存となる。プロジェクトをまたいで蓄積を共有したい場合は保存先をホームディレクトリ配下（例: `~/.claude/design-library.json`）に変更する派生版も検討に値する。
- `/design-apply` の融合ロジックは本仕様では「Claudeが判断」としているが、より精度を高める場合は「参照比率を数値で指定できる」オプション（例: `/design-apply --ratio a.com:70 b.com:30 LPを作れ`）の追加が有効。
