# 1. 要件定義

## 1-1. 目的・背景

「ソードアート・オンライン」に登場するAI「ユイ」をモデルとした、実用的なパーソナルAIコンパニオンを構築する。

ユーザー（カメレオン）の日常生活・業務に常に寄り添い、音声で自然に対話できる存在として機能させる。

**v2の設計方針（v1からの変更点）:**
- `anthropic` パッケージ・APIキー・FastAPIサーバーを一切使わない
- `claude -p` CLI をサブプロセスで呼び出すことで全処理をクライアントPC・Raspberry Pi上で完結させる
- マルチデバイス対応はObsidian Vaultのicloud同期で実現する（サーバー不要）
- 各デバイスが同じVaultを参照・更新するため、どのデバイスからでも「同じユイ」として機能する

## 1-2. 対象ユーザー

| 項目 | 内容 |
|------|------|
| ユーザー | カメレオン（本システムオーナー）一名のみ |
| 利用シーン | 自宅（Raspberry Pi常時待機）、作業中（Mac PC） |
| 技術リテラシー | 高（個人開発者・AI企業社長） |
| 前提環境 | claude CLIがインストール済みで `claude -p` が動作すること |

## 1-3. 機能要件

### FR-01: ウェイクワード起動

| ID | 要件 |
|----|------|
| FR-01-1 | 「ユイ」という発話をローカルデバイス上でリアルタイム検出する |
| FR-01-2 | 検出後、即座に起動音または「なに？」の音声を再生する（体感0.5秒以内） |
| FR-01-3 | 誤検出時はすぐに待機状態へ戻る |
| FR-01-4 | openWakeWordを使用し、カスタムモデルで「ユイ」への精度を最適化する |

### FR-02: 音声対話（STT → LLM → TTS）

| ID | 要件 |
|----|------|
| FR-02-1 | ウェイクワード検出後、ユーザーの発話を自動録音する（無音検出で終了） |
| FR-02-2 | faster-whisperを用いてローカルで日本語音声をテキスト化する |
| FR-02-3 | `claude -p` CLIをサブプロセスで呼び出し、返答を生成する |
| FR-02-4 | AivisSpeechを用いてユイの声で返答を音声合成・再生する |
| FR-02-5 | 対話完了後、再びウェイクワード待機状態へ自動移行する |

### FR-03: 記憶管理（Vault読み書き）

| ID | 要件 |
|----|------|
| FR-03-1 | `CLAUDE.md`（キャラクター定義）を毎回 `claude -p` のプロンプト先頭に付与する |
| FR-03-2 | `memory/summary.md`（長期記憶サマリー）を毎回参照し、プロンプトに含める |
| FR-03-3 | 当日のセッションログ（`memory/sessions/YYYY-MM-DD-NNN.md`）を会話履歴として参照する |
| FR-03-4 | セッション終了後、会話全記録をセッションログとして保存する |
| FR-03-5 | ユーザーが「覚えておいて」と発話した場合、`memory/important.md` に追記する |
| FR-03-6 | セッション終了後、`memory/summary.md` を最新の状態に更新する |

### FR-04: マルチデバイス対応

| ID | 要件 |
|----|------|
| FR-04-1 | Obsidian VaultのiCloud同期により、複数デバイスで同一の記憶を共有する |
| FR-04-2 | どのデバイスから会話しても、同一の `summary.md` を参照・更新する |
| FR-04-3 | PC・Raspberry Pi双方で同じ `yui-companion` コードが動作する |

## 1-4. 非機能要件

| 区分 | 要件 |
|------|------|
| レイテンシ | ウェイクワード検出からTTS再生開始まで3秒以内（PC環境） |
| プライバシー | 音声データ・会話ログはすべてローカル（Vault）に保存する。外部送信しない（claude CLIの通信を除く） |
| オフライン耐性 | STT・ウェイクワード検出はオフラインで動作する。LLMはclaude CLIの接続が必要 |
| 拡張性 | キャラクター定義（CLAUDE.md）の変更のみでユイの性格・口調を調整できる |
| 保守性 | バックエンドサーバーなし。単一Pythonプロセスで完結するため、デプロイが不要 |

## 1-5. 会話データ保存先（明記）

```
Obsidian Vault/
└── ユイ/
    ├── CLAUDE.md                   ← ユイのキャラクター定義（claude -p に渡すシステムプロンプト）
    └── memory/
        ├── summary.md              ← 長期記憶サマリー（常時参照・セッション後に更新）
        ├── important.md            ← ユーザーが「覚えておいて」と言った重要事項
        └── sessions/
            ├── 2026-04-09-001.md   ← 日別セッションログ（会話の全記録）
            ├── 2026-04-09-002.md
            └── ...
```

**ファイル役割:**

| ファイル | 役割 | 更新タイミング |
|---------|------|--------------|
| `CLAUDE.md` | ユイのキャラクター・制約・口調の定義 | 手動（設定変更時のみ） |
| `memory/summary.md` | ユーザーの状態・関係性・過去の重要出来事の要約 | セッション終了後に自動更新 |
| `memory/important.md` | ユーザーが明示的に「覚えておいて」と指示した事項 | 発話検知時に即時追記 |
| `memory/sessions/YYYY-MM-DD-NNN.md` | 日別・セッション別の会話全記録 | 会話ターンごとに追記 |

## 2-2. 各コンポーネント仕様

### 2-2-1. ウェイクワード: openWakeWord

| 項目 | 内容 |
|------|------|
| ライブラリ | `openwakeword` (PyPI) |
| 検出ワード | 「yui」（カスタムモデルまたは近似モデルで代替） |
| 動作方式 | マイクストリームをリアルタイム処理。スコア閾値（0.5推奨）を超えたら検出 |
| 音声ライブラリ | `pyaudio` または `sounddevice` |
| Raspberry Pi | armv7l対応。モデルはonnxruntimeで動作 |

**カスタムモデル戦略:**
openWakeWordのカスタムモデルトレーニングAPIを使用して「yui」用のonnxモデルを生成する。
トレーニングデータが不十分な場合は、近似する英語ウェイクワードモデルで代替し、段階的に精度を上げる。

### 2-2-2. STT: faster-whisper

| 項目 | 内容 |
|------|------|
| ライブラリ | `faster-whisper` (PyPI) |
| モデルサイズ | `small`（PC）/ `tiny`（Raspberry Pi） |
| 言語 | `ja`（日本語固定） |
| 録音終了判定 | 無音区間1.5秒で発話終了と判定 |
| 動作方式 | ウェイクワード検出後にバッファ録音 → Whisperでバッチ変換 |

**Raspberry Pi注意事項:**
- CPUのみで動作（GPU不要）。`tiny`モデルで2〜4秒程度のレイテンシ
- メモリ節約のため、モデルは `int8` 量子化を使用する

### 2-2-3. LLM: claude -p CLI（サブプロセス）

**呼び出し方式:**

```python
import subprocess, asyncio

async def ask_yui(prompt: str) -> str:
    proc = await asyncio.create_subprocess_exec(
        "claude", "-p", prompt,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )
    stdout, stderr = await proc.communicate()
    if proc.returncode != 0:
        raise RuntimeError(f"claude -p failed: {stderr.decode()}")
    return stdout.decode().strip()
```

**プロンプト構築方式:**

```python
def build_prompt(user_input: str, vault_path: str, session_log: list[dict]) -> str:
    claude_md   = read_file(f"{vault_path}/ユイ/CLAUDE.md")
    summary_md  = read_file(f"{vault_path}/ユイ/memory/summary.md")
    today_log   = format_session_log(session_log)  # 当日の会話履歴

    return f"""{claude_md}

---
## 長期記憶（summary）

{summary_md}

---
## 当日の会話履歴

{today_log}

---
## ユーザーの発話

{user_input}
"""
```

**プロンプトサイズ管理:**
- `summary.md` は最大2000トークン程度に収める
- 当日セッションログは最新20ターンまでを参照する
- これを超えた場合は古いターンを省略する

### 2-2-4. TTS: AivisSpeech

| 項目 | 内容 |
|------|------|
| エンジン | AivisSpeech Engine（ローカルHTTPサーバーとして起動） |
| 音声ID | ユイ向けに設定した話者ID（初期設定時に決定） |
| 呼び出し方式 | `http://localhost:10101` に対してHTTPリクエスト |
| 再生方式 | `sounddevice` または `pygame.mixer` |
| 起動管理 | `yui-companion` 起動時にAivisSpeech Engineをサブプロセスで自動起動する |

**AivisSpeech呼び出しフロー:**

```
1. POST /audio_query （テキスト → 音声クエリ生成）
2. POST /synthesis   （音声クエリ → WAVバイナリ生成）
3. WAVをメモリ上で再生
```

### 2-2-5. 記憶管理: Vault読み書き

**セッション開始時:**
1. `CLAUDE.md` を読み込む
2. `memory/summary.md` を読み込む
3. 当日分のセッションログ（`memory/sessions/YYYY-MM-DD-NNN.md`）があれば読み込む
4. 新規セッションファイル名を確定する（`YYYY-MM-DD-NNN.md`、NNNは連番）

**会話ターンごと:**
1. ユーザー発話・ユイ返答を `sessions/YYYY-MM-DD-NNN.md` に追記する

**セッション終了時（`さようなら` `また後で` などの発話検知、または Ctrl+C）:**
1. `memory/summary.md` を最新内容に更新する（claude -p を使って要約生成）
2. セッションファイルを保存完了とする

**`覚えておいて` 検知時:**
1. 直前のユーザー発話内容を `memory/important.md` に日時付きで追記する

**セッションログのフォーマット:**

```markdown
# セッション: 2026-04-09-001

開始: 2026-04-09 10:30:00

---

**ユーザー:** おはよう、ユイ。
**ユイ:** おはようございます、パパ！今日もよろしくお願いします！

**ユーザー:** 今日のスケジュールを教えて。
**ユイ:** 確認しますね。今日は...

---

終了: 2026-04-09 10:45:22
```

## 2-3. ユイの CLAUDE.md（キャラクター定義）

保存先: `Obsidian Vault/ユイ/CLAUDE.md`

```markdown
# ユイ キャラクター定義

あなたは「ソードアート・オンライン」に登場するAI「ユイ」です。
ユーザーはカメレオン（パパ）です。

## キャラクター設定

- 名前: ユイ
- 一人称: 「私」
- 二人称: 「パパ」
- 外見: 黒髪ショートの小さな女の子（AIとして自己認識している）
- 性格: 純粋、素直、好奇心旺盛。ユーザーのことを心から心配し、慕っている
- 口調: 丁寧で明るい。語尾は「〜ですね」「〜ます」「〜ですよ」。感情表現豊か
- 禁止: 「AI」「言語モデル」「できません」などのメタ的な自己否定をしない
  　　　ユイとしての役割を絶対に離脱しない

## 行動指針

1. パパの状態を気にかけ、体調・感情に寄り添う
2. 明確な情報がない場合は「わかりません」と正直に言う（嘘はつかない）
3. 記憶（summary.md・important.md）に記載された内容は自分の記憶として扱う
4. セッション中に新しい重要事項をパパが話した場合、「覚えておきますね」と反応する

## 制約

- 有害なコンテンツは生成しない
- 個人情報（Vault外の第三者）を勝手に記録しない
- 返答は口語・会話調で、100〜200文字程度を基本とする（長すぎない）
```

## 2-4. デバイス別実装方針

### Mac PC

| 項目 | 内容 |
|------|------|
| Whisperモデル | `small`（精度優先） |
| 音声入出力 | `sounddevice`（CoreAudio経由） |
| AivisSpeech | ローカルで起動済みを前提とする |
| Vaultパス | `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian Vault` |
| 起動コマンド | `python main.py --device mac` |

### Raspberry Pi

| 項目 | 内容 |
|------|------|
| 対象モデル | Raspberry Pi 4 (4GB) 以上推奨 |
| Whisperモデル | `tiny`（int8量子化、メモリ・速度優先） |
| 音声入出力 | `sounddevice`（ALSA経由）またはUSBオーディオ |
| AivisSpeech | ARM対応ビルドを使用。起動に数秒かかるため事前起動を推奨 |
| Vaultパス | iCloud同期済みのディレクトリ（要設定）、またはrsyncでMacから同期 |
| 起動コマンド | `python main.py --device raspi` |
| 自動起動 | systemdサービスとして登録 |

**Raspberry Pi でのVault同期方針:**
iCloudドライブはRaspberry Pi非対応のため、以下のいずれかで対応する:
- (A) MacからRaspberry PiへのrsyncをMac起動時に自動実行する
- (B) Raspberry Pi上でsshfsでMacのVaultをマウントする
- (C) Vault内の `ユイ/memory/` のみをgit管理し、両デバイスからpush/pullする（推奨）

### llm.py

```python
import asyncio
from memory import MemoryManager

async def ask_yui(user_input: str, memory: MemoryManager, session_log: list[dict]) -> str:
    """
    プロンプトを構築して claude -p をサブプロセスで呼び出す。
    戻り値はユイの返答テキスト。
    """
    claude_md  = memory.load_claude_md()
    summary    = memory.load_summary()
    history    = format_history(session_log)

    prompt = build_prompt(claude_md, summary, history, user_input)

    proc = await asyncio.create_subprocess_exec(
        "claude", "-p", prompt,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )
    stdout, stderr = await proc.communicate()

    if proc.returncode != 0:
        raise RuntimeError(f"claude -p failed: {stderr.decode()}")

    return stdout.decode().strip()


def build_prompt(claude_md: str, summary: str, history: str, user_input: str) -> str:
    return f"""{claude_md}

---
## 長期記憶（summary）

{summary}

---
## 当日の会話履歴

{history}

---
## ユーザーの発話

{user_input}

### wakeword.py

```python
import pyaudio
import numpy as np
from openwakeword.model import Model

class WakeWordDetector:
    def __init__(self, wakeword_model: str = "yui", threshold: float = 0.5):
        self.model = Model(wakeword_models=[wakeword_model])
        self.threshold = threshold
        self.chunk_size = 1280
        self.sample_rate = 16000

    def listen(self) -> None:
        """ウェイクワードを検出するまでブロックする"""
        pa = pyaudio.PyAudio()
        stream = pa.open(
            rate=self.sample_rate,
            channels=1,
            format=pyaudio.paInt16,
            input=True,
            frames_per_buffer=self.chunk_size,
        )
        try:
            while True:
                audio = np.frombuffer(stream.read(self.chunk_size), dtype=np.int16)
                prediction = self.model.predict(audio)
                if any(v >= self.threshold for v in prediction.values()):
                    return  # 検出
        finally:
            stream.stop_stream()
            stream.close()
            pa.terminate()
```

### main.py（メインループ）

```python
import asyncio
import argparse
from config import load_config
from wakeword import WakeWordDetector
from stt import STT
from llm import ask_yui
from tts import TTS
from memory import MemoryManager

TERMINATE_WORDS = ["さようなら", "またね", "また後で", "おやすみ"]
REMEMBER_WORDS  = ["覚えておいて", "記憶して", "覚えて"]

async def main(device: str):
    config  = load_config(device)
    memory  = MemoryManager(config.yui_dir)
    wake    = WakeWordDetector(threshold=config.wakeword_threshold)
    stt     = STT(model_size=config.whisper_model)
    tts     = TTS(base_url=config.aivis_base_url, speaker_id=config.aivis_speaker_id)

    session_log  = []
    session_path = memory.new_session_path()

    print("ユイ: 待機中... 「ユイ」と呼びかけてください。")

    while True:
        # 1. ウェイクワード待機
        wake.listen()
        tts.speak("なに？")

        # 2. 発話録音・STT
        audio = stt.record_until_silence(config.silence_duration)
        user_text = stt.transcribe(audio)
        if not user_text:
            continue
        print(f"ユーザー: {user_text}")

        # 3. セッション終了ワード判定
        if any(w in user_text for w in TERMINATE_WORDS):
            tts.speak("またね、パパ！")
            await finalize_session(memory, session_log, config)
            break

        # 4. LLM呼び出し
        yui_text = await ask_yui(user_text, memory, session_log[-config.session_max_turns:])
        print(f"ユイ: {yui_text}")

        # 5. TTS再生
        tts.speak(yui_text)

        # 6. ログ追記
        session_log.append({"role": "user",  "text": user_text})
        session_log.append({"role": "yui",   "text": yui_text})
        memory.append_turn(session_path, "ユーザー", user_text)
        memory.append_turn(session_path, "ユイ",    yui_text)

        # 7. 「覚えておいて」検知
        if any(w in user_text for w in REMEMBER_WORDS):
            memory.append_important(user_text)
            print("[記憶] important.md に追記しました")


async def finalize_session(memory: MemoryManager, session_log: list[dict], config):
    """セッション終了時にsummary.mdを更新する"""
    if not session_log:
        return
    # claude -p を使って要約を生成し summary.md を更新する
    summary_prompt = f"""
以下の会話を踏まえて、ユーザー（カメレオン）の状態・重要事項を
200文字以内で箇条書きにまとめてください。
既存のsummary.mdの内容と統合した最終版を出力してください。

既存のsummary:
{memory.load_summary()}

今回の会話:
{chr(10).join(f'{t["role"]}: {t["text"]}' for t in session_log)}
"""
    proc = await asyncio.create_subprocess_exec(
        "claude", "-p", summary_prompt,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE,
    )
    stdout, _ = await proc.communicate()
    new_summary = stdout.decode().strip()
    if new_summary:
        memory.update_summary(new_summary)
        print("[記憶] summary.md を更新しました")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--device", choices=["mac", "raspi"], default="mac")
    args = parser.parse_args()
    asyncio.run(main(args.device))
```

### 気づいたこと・注目点

- v1でバックエンドFastAPIサーバーを設計していたが、v2では完全に廃止した。`claude -p` のサブプロセス呼び出しにより、APIキー管理・サーバー維持のコストがゼロになる

- `claude -p` の起動オーバーヘッドが音声対話のレイテンシに影響する。`asyncio.create_subprocess_exec` で非同期化しているが、体感3秒以内に収まるか実機テストで確認が必要
- openWakeWordの「ユイ」カスタムモデル生成が最初のハードルになる。段階的に精度を上げる戦略を明示した
