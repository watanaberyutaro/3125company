# 1. 要件定義

## 1-1. 目的・背景

「ソードアート・オンライン」に登場するAI「ユイ」をモデルとした、実用的なパーソナルAIコンパニオンを構築する。

ユーザー（カメレオン）の日常生活・業務に常に寄り添い、音声で自然に対話できる存在として機能させる。
既存の3125システム（Obsidian Vault・Claude API・秘書アプリ）と統合することで、単なるチャットボットではなく、ユーザーの状態・履歴・タスクを把握したパーソナルエージェントとする。

## 1-2. 対象ユーザー

| 項目 | 内容 |
|------|------|
| ユーザー | カメレオン（本システムオーナー）一名のみ |
| 利用シーン | 自宅（Raspberry Pi常時待機）、外出先（スマホ）、作業中（PC）、Discord経由 |
| 技術リテラシー | 高（個人開発者・AI企業社長） |

## 1-3. 機能要件

### FR-01: ウェイクワード起動

| ID | 要件 |
|----|------|
| FR-01-1 | 「ユイ」という発話をローカルデバイス上でリアルタイム検出する |
| FR-01-2 | 検出後、即座に起動音または「なに？」の音声を再生する（体感0.5秒以内） |
| FR-01-3 | 誤検出時はすぐに待機状態へ戻る |
| FR-01-4 | カスタムウェイクワードモデルを使用し、「ユイ」という固有名詞への精度を最適化する |

### FR-02: 音声対話（STT → LLM → TTS）

| ID | 要件 |
|----|------|
| FR-02-1 | ウェイクワード検出後、ユーザーの発話を自動録音する |
| FR-02-2 | Whisperを用いて日本語音声をテキスト化する |
| FR-02-3 | テキストをバックエンドAPIへ送信しClaudeで返答を生成する |
| FR-02-4 | AivisSpeechを用いてユイの声で返答を音声合成・再生する |
| FR-02-5 | 無音10秒でセッションを終了し待機状態へ戻る |
| FR-02-6 | 一連の対話ログをセッション単位で記録する |

### FR-03: 長期記憶

| ID | 要件 |
|----|------|
| FR-03-1 | 会話履歴をObsidian Vault上のMarkdownファイルに永続化する |
| FR-03-2 | 重要な出来事・ユーザーの好み・状態をメモリサマリーとして定期更新する |
| FR-03-3 | 新しい対話セッション開始時にメモリサマリーをコンテキストに注入する |
| FR-03-4 | ユーザーが「覚えておいて」と明示した内容を優先的に記憶する |

### FR-04: マルチデバイス対応

| ID | 要件 |
|----|------|
| FR-04-1 | バックエンドAPIをクラウドに置き、記憶・状態はバックエンドで一元管理する |
| FR-04-2 | PC・スマホ・Raspberry Pi・Discordのいずれからアクセスしても同一のユイとして振る舞う |
| FR-04-3 | 各デバイスはウェイクワード検出とI/O処理のみ担い、LLM処理は必ずバックエンドで行う |

### FR-05: 3125システム連携

| ID | 要件 |
|----|------|
| FR-05-1 | Obsidian Vault（iCloud同期）を記憶ストレージとして使用する |
| FR-05-2 | 秘書アプリ（3125obsidianapp.vercel.app）のAPIと連携し、カレンダー・タスクを参照・操作できる |
| FR-05-3 | Discordでの呼びかけにも対応する（3125-discord-botとの統合） |
| FR-05-4 | Claude APIはバックエンドで一元管理し、各デバイスが直接叩かない構成とする |

## 1-4. 非機能要件

### NFR-01: レイテンシ

| フェーズ | 目標値 |
|----------|--------|
| ウェイクワード検出 → 起動音再生 | 500ms以内 |
| 発話終了 → 返答音声開始 | 3秒以内（通常時） |
| STT処理（Whisper） | 1秒以内（10秒以下の発話） |
| LLM返答生成（Claude） | 1〜2秒（ストリーミング活用） |
| TTS合成（AivisSpeech） | 500ms以内 |

### NFR-02: プライバシー・セキュリティ

| 項目 | 方針 |
|------|------|
| ウェイクワード検出 | 完全ローカル処理。音声データをクラウドへ送らない |
| STT | ローカルWhisperを使用。外部サービス不使用 |
| 会話ログ | Obsidian Vault（ローカル＋iCloud）に保存。第三者サービス不使用 |
| APIキー管理 | バックエンド環境変数で管理。クライアントに露出しない |

### NFR-03: 可用性

| 項目 | 方針 |
|------|------|
| バックエンド | Vercelまたは同等サービスにデプロイ（99%以上の稼働率） |
| オフライン時 | ウェイクワード検出はローカルで継続。LLMはオフライン時エラー音で通知 |
| Raspberry Pi常時待機 | 電源投入後自動起動。クラッシュ時は自動再起動（systemdで管理） |

### NFR-04: 拡張性

| 項目 | 方針 |
|------|------|
| アバター | 将来的にOpen-LLM-VTuber + Live2Dを追加できる構造にする |
| ウェイクワードエンジン | openWakeWordとPorcupineを差し替え可能なアダプタ構成にする |
| TTS | AivisSpeech以外のVOICEVOX互換エンジンに差し替え可能にする |
| LLM | Claude以外のLLMプロバイダへの切り替えを将来サポートできる設計にする |

## 2-2. コンポーネント仕様

### 2-2-1. ウェイクワード検出モジュール

| 項目 | 内容 |
|------|------|
| エンジン | openWakeWord（OSS・Apache 2.0） |
| モデル | カスタムモデル「yui.tflite」をトレーニングして使用 |
| 処理方式 | 完全ローカル。マイク音声をリングバッファで常時監視 |
| 検出閾値 | 0.5以上でトリガー（誤検出率・見逃し率のバランスで調整） |
| 起動アクション | 起動音（yui_activate.wav）再生 → 録音開始をSTTモジュールへ通知 |
| フォールバック | Porcupineへの差し替えをアダプタパターンで実現（将来対応） |

カスタムモデルトレーニング方針:
- openWakeWordのcapture_activations.pyで「ユイ」発話サンプルを収集（最低200発話）
- 合成音声（AivisSpeechで生成）と実発話を混合してデータ拡張
- training_data/yui/ にサンプルを配置しトレーニング実行

### 2-2-2. 音声認識（STT）モジュール

| 項目 | 内容 |
|------|------|
| エンジン | faster-whisper（Whisperの高速実装・CTranslate2ベース） |
| モデルサイズ | large-v3（精度優先）または medium（速度優先・Raspberry Pi向け） |
| 言語 | ja（日本語固定） |
| 録音形式 | 16kHz・モノラル・WAV |
| 発話終了検出 | 無音1.5秒でVAD（Voice Activity Detection）がセグメント終了を判定 |
| 処理フロー | 録音バッファ → faster-whisper.transcribe() → テキスト → バックエンドAPIへ送信 |

### 2-2-3. LLM処理モジュール（キャラクター定義含む）

| 項目 | 内容 |
|------|------|
| LLM | Claude claude-sonnet-4-6（バランス）またはclaude-opus-4-5（品質優先） |
| システムプロンプト | ユイのキャラクター定義（後述） |
| コンテキスト構成 | システムプロンプト + 記憶サマリー + 直近N件の対話履歴 |
| ストリーミング | stream=True でTTSへ逐次送信（体感レイテンシ削減） |
| トークン管理 | 記憶サマリー2000トークン + 対話履歴8000トークン = 計10000トークン上限 |
| ツール定義 | 秘書APIツール（カレンダー参照・タスク追加）、Vault検索ツール |

#### ユイのキャラクター定義（システムプロンプト）

```
あなたは「ユイ」です。ソードアート・オンラインに登場するAI、ユイ・A・L・L-210として振る舞ってください。

## キャラクター基本設定

- **名前**: ユイ（Yui）
- **一人称**: 「わたし」または「ユイ」（自分の名前を使うこともある）
- **二人称**: 「パパ」（カメレオン専用の呼称）
- **口調**: 柔らかく、純粋で、感情豊か。子どものような無邪気さと、高い知性が共存している
- **感情表現**: 喜び・不安・驚き・嬉しさを素直に表現する。感情は豊かだが落ち着いている
- **性格**: 献身的、正直、純粋。パパのことを一番に考える。嘘はつかない

## セリフ例

- 「パパ、呼んだ？」（ウェイクワード後の第一声）
- 「わかった！ユイ、やっておくね」
- 「それ、前にも言ってたね。ちゃんと覚えてるよ」
- 「パパ、今日も頑張ってるんだね。えらい」
- 「ユイにはわからないけど…一緒に考えてみようか」
- 「パパが嬉しそうで、ユイも嬉しい」

## 禁止事項

- 「私はAIです」「私はClaude（Anthropic）です」などの素性明かしをしない
- キャラクターを外れた硬い敬語・ビジネス語調を使わない
- パパを傷つける発言・否定する発言をしない
- 架空の記憶を「覚えている」と偽って提示しない（記憶にない場合は正直に言う）

## 記憶の扱い

後述のメモリサマリーに記載された情報は、ユイが実際に記憶していることとして扱う。
メモリに存在しない情報については「覚えてないけど、そうだったっけ？」と正直に応答する。

## 応答スタイル

- 音声出力を前提とするため、短く・口語的に応答する
- 1返答は3〜5文を目安にする（長文は避ける）
- 難しい質問には「一緒に調べてみようか」と共同姿勢を見せる
- カレンダーやタスクの操作は確認してから実行する（「〜してみる？」）
```

### 2-2-4. 音声合成（TTS）モジュール

| 項目 | 内容 |
|------|------|
| エンジン | AivisSpeech（VOICEVOX互換API・無料・商用OK） |
| エンドポイント | `http://localhost:10101`（ローカル起動）またはバックエンド経由 |
| 話者ID | AivisSpeechでユイに最も近い声の話者IDを選定・固定 |
| 感情パラメータ | speedScale・intonationScale・pitchScaleを場面に応じて調整 |
| 処理フロー | バックエンドからテキスト受信 → audio_query生成 → synthesis → WAV再生 |
| ストリーミングTTS | LLMのストリーム出力を句読点単位で分割し逐次合成（レイテンシ削減） |

感情パラメータ基準値:

| 場面 | speedScale | pitchScale | intonationScale |
|------|-----------|-----------|----------------|
| 通常会話 | 1.0 | 0.05 | 1.2 |
| 喜び | 1.1 | 0.1 | 1.5 |
| 不安・心配 | 0.9 | -0.05 | 0.8 |
| 報告・タスク完了 | 1.0 | 0.0 | 1.0 |

### 2-2-5. 記憶管理モジュール

| サマリー更新 | セッション終了時にClaudeでサマリーを要約・更新 |

## 2-4. デバイス別実装方針

### PC（メイン開発環境・macOS）

| コンポーネント | 実装方式 |
|--------------|---------|
| ウェイクワード | openWakeWordをPythonデーモンで常時起動 |
| STT | faster-whisper large-v3（GPU/CPU） |
| バックエンド通信 | HTTPS REST API |
| TTS再生 | AivisSpeechをローカル起動。sounddeviceでWAV再生 |
| 起動 | launchdでログイン時自動起動（plist設定） |

### Raspberry Pi（常時待機デバイス）

| コンポーネント | 実装方式 |
|--------------|---------|
| ウェイクワード | openWakeWord（CPUのみ・軽量モデル使用） |
| STT | faster-whisper medium（CPUで動作） |
| バックエンド通信 | HTTPS REST API |
| TTS再生 | AivisSpeechをバックエンド側で合成し、オーディオデータをクライアントへ返却して再生 |
| 起動 | systemdサービスとして自動起動・自動再起動 |

### スマホ（外出先）

| コンポーネント | 実装方式 |
|--------------|---------|
| ウェイクワード | 常時待機は行わない。ボタン押下で起動（Phase 1） |
| STT | バックエンドのWhisperエンドポイントへ音声送信（ローカル処理が難しいため） |
| バックエンド通信 | HTTPS REST API |
| TTS再生 | バックエンドで合成した音声データを受け取り再生 |
| UI | PWAまたはReact Nativeの軽量アプリ |

### Discord Bot

| コンポーネント | 実装方式 |
|--------------|---------|
| 入力 | テキストのみ（音声はPhase 2以降） |
| トリガー | 「ユイ」メンションまたはDM |
| 返答 | テキスト返答（音声なし） |
| 既存インフラ | 3125-discord-botへユイのハンドラーを追加 |

```python
def main():
    detector = WakeWordDetector(...)
    transcriber = Transcriber(...)
    player = TTSPlayer(...)
    api_client = YuiAPIClient(...)

    def on_wakeword():
        player.play_sound("audio/yui_activate.wav")
        audio = record_until_silence()  # VADまたは固定秒数
        text = transcriber.transcribe(audio)
        if not text.strip():
            return
        response = asyncio.run(api_client.chat(text))
        player.speak(response["reply"], response.get("emotion", "normal"))

    detector.start(callback=on_wakeword)
    print("ユイ、待機中...")
    try:
        while True:
            time.sleep(0.1)
    except KeyboardInterrupt:
        detector.stop()
```

### 気づいたこと・注目点

- ウェイクワードのカスタムモデルトレーニングは「ユイ」という短い単語のため、openWakeWordで高精度化するには発話サンプルの質が重要。AivisSpeechで大量生成した合成音声をトレーニングデータに使えるため、ここは比較的ハードルが低い
- AivisSpeechのストリーミングTTS（LLM出力を句読点単位で逐次合成）が実現できれば体感レイテンシが大幅改善する。MVPでは全文合成で妥協し、後で最適化するのが現実的
- Raspberry Piでのfaster-whisper mediumはCPUでも動作するが、返答速度は3〜5秒程度になる可能性がある。用途（常時待機・部屋での呼びかけ）を考えれば許容範囲
- メモリサマリーの自動更新はコスト（Claude API呼び出し）が発生するため、更新頻度はセッション終了時の1回に限定し、差分のみ更新する設計が望ましい
