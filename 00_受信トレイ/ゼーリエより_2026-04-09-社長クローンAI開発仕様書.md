# 社長人格クローンAI「佐藤和人クローン」開発仕様書

---

## 1. 要件定義

### 1-1. 目的・背景

社長（佐藤一斗）の人格・知識・価値観・判断軸を模倣したWebチャットAIを構築し、社員が日常業務における判断・確認行為を社長本人に依存せずに処理できる状態を作る。

**ロードマップ:**

| フェーズ | 内容 | 目標 |
|---------|------|------|
| Phase 1（MVP） | 自社社員向けに社内展開。Mac上でサーバー起動 | ユースケース収集・精度検証 |
| Phase 2（本番） | Windows PC（常時起動）に移行。社内正式運用 | 社長の代替窓口として定着 |
| Phase 3（SaaS化） | 他社向けに「経営者クローンAI」としてサービス展開 | 受託 → サブスク型収益化 |

### 1-2. 対象ユーザー

| フェーズ | ユーザー | アクセス方法 |
|---------|---------|------------|
| Phase 1 | 自社社員（限定） | VercelホストのチャットUI（社内URL共有） |
| Phase 2 | 自社社員（全員） | 同上（Google認証で制限） |
| Phase 3 | 他社経営者・社員 | SaaSプラットフォーム（別途設計） |

### 1-3. 機能要件

| ID | 機能 | 説明 |
|----|------|------|
| FR-01 | チャット機能 | ユーザーが質問を入力し、クローンAIが回答を返す |
| FR-02 | RAG検索 | 質問に関連する過去発言・社内ルールをベクトル検索し回答に付加する |
| FR-03 | 人格再現 | 佐藤和人の口調・判断パターン・価値観で回答する |
| FR-04 | 社内認証 | Googleアカウントログインで社員のみアクセスを制限する |
| FR-05 | データ投入 | LINEエクスポート・就業規則PDF等をRAGに取り込むスクリプトを提供する |

### 1-4. 非機能要件

| 項目 | 目標値 | 備考 |
|------|--------|------|
| 回答精度 | 社員が「社長らしい」と感じる割合 80%以上 | Phase 1の定性評価で判断 |
| レイテンシ | 質問投稿から回答表示まで 15秒以内 | `claude -p` のサブプロセス起動コストを含む |
| 可用性 | 平日 9:00〜22:00 稼働 | Phase 1は Mac起動中のみ。Phase 2は常時起動PC |
| コスト | Claude API費用ゼロ | `claude -p` CLI（無料枠）を使用。ベクトル処理はローカル完結 |
| セキュリティ | 社内データの外部送信なし | ChromaDB・sentence-transformers はローカル処理 |

### 2-4. データ収集・整形方法

**LINEエクスポート（人格データ）:**

1. LINEアプリ → トーク → 右上メニュー → 「トーク履歴を送信」→ テキスト形式でエクスポート
2. エクスポート形式: `YYYY/MM/DD HH:MM\t送信者名\tメッセージ本文`
3. `line_parser.py` が佐藤和人の発言行のみ抽出し、チャンク化する
4. 投入時メタデータ: `{ source: "line", category: "personality", date: "YYYY-MM-DD" }`

**就業規則・社内ルール（制度データ）:**

1. PDF形式で `data/raw/` に配置
2. `pdf_parser.py` が `pdfminer.six` でテキスト抽出
3. 300文字チャンク・50文字オーバーラップで分割
4. 投入時メタデータ: `{ source: "pdf", category: "rules", date: "YYYY-MM-DD" }`

**思想・理念テキスト（思想データ）:**

1. 経営方針・会社への思い等を手書きテキストまたはMarkdownで作成
2. `data/raw/philosophy.txt` に配置
3. `ingest_runner.py` がそのまま取り込む
4. 投入時メタデータ: `{ source: "manual", category: "philosophy", date: "YYYY-MM-DD" }`

### 2-6. claude -p 呼び出しコード（Python asyncio）

```python
# llm/runner.py

import asyncio
import subprocess
from llm.prompt_builder import build_prompt

async def run_claude(message: str, context_chunks: list[str], history: list[dict]) -> str:
    prompt = build_prompt(message, context_chunks, history)

    proc = await asyncio.create_subprocess_exec(
        "claude", "-p", prompt,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )

    stdout, stderr = await proc.communicate()

    if proc.returncode != 0:
        raise RuntimeError(f"claude -p failed: {stderr.decode()}")

    return stdout.decode().strip()
```

```python
# llm/prompt_builder.py

SYSTEM_BASE = open("system_prompt/sato_kazuto.txt", encoding="utf-8").read()

def build_prompt(message: str, context_chunks: list[str], history: list[dict]) -> str:
    context_text = "\n\n".join(f"- {c}" for c in context_chunks)
    history_text = "\n".join(
        f"{'社員' if h['role'] == 'user' else '佐藤和人'}: {h['content']}"
        for h in history[-6:]  # 直近3往復
    )

    return f"""{SYSTEM_BASE}

## 参考発言・関連情報（RAGで取得）
{context_text}

## 直近の会話履歴
{history_text}

## 今回の質問
{message}

上記をふまえ、佐藤和人として回答してください。"""
```

**system_prompt/sato_kazuto.txt 雛形:**

```
あなたは佐藤和人です。以下の情報をもとに、佐藤和人として回答してください。

## 佐藤和人のプロフィール・価値観
（ここに人格・思想データを記載。例: 決断は早く、曖昧な態度を嫌う。社員への期待値は高いが情に厚い。）

## 会社のルール・制度

## 回答ルール
- わからないことは「わからない」と正直に答える
- 佐藤和人の口調・言い回しで回答する
- 回答は簡潔に。長くなる場合は要点を先に述べる
- 個人的な感情や推測を事実として語らない
```

```
## 実装対象
ingest/ フォルダ配下の3ファイル + 実行スクリプト

### line_parser.py の詳細仕様
- 引数: file_path: str, sender_name: str
- LINEエクスポートTXTは UTF-8 エンコーディング
- 1行の形式: "YYYY/MM/DD HH:MM\t{送信者名}\t{メッセージ}"
- 日付行（"YYYY年MM月DD日（曜日）" 形式）はスキップ
- システムメッセージ（「〜が参加しました」等）はスキップ
- sender_name に一致する発言のみ抽出
- 返却: list[str]（メッセージ本文のリスト）
- チャンクサイズ: 1発言 = 1チャンク（分割しない）

### pdf_parser.py の詳細仕様
- 引数: file_path: str
- pdfminer.six の extract_text を使用
- 抽出後、改行・空白の正規化を行う
- chunk_size=300文字, overlap=50文字でスライディングウィンドウ分割
- 返却: list[str]

### ingest_runner.py の詳細仕様
コマンドライン例:
  python ingest_runner.py --category personality --file data/raw/line.txt --sender 佐藤和人
  python ingest_runner.py --category rules --file data/raw/rules.pdf
  python ingest_runner.py --category philosophy --file data/raw/philosophy.txt

処理フロー:
1. カテゴリに応じたパーサーを呼び出し chunks: list[str] を取得
2. embedder.encode(chunks) で埋め込みベクトル取得
3. metadatas = [{"source": file_path, "category": category, "date": today} for _ in chunks]
4. vectorstore.add_chunks(chunks, embeddings, metadatas)
5. 完了メッセージ表示: f"{len(chunks)} チャンクを投入しました"

## 注意事項
- エラー時は明確なエラーメッセージを stderr に出力する
- 大量データ投入時のメモリ効率を考慮し、バッチ処理（batch_size=64）で埋め込みを生成する
```

### 気づいたこと・注目点

- `claude -p` のサブプロセス起動コストは1回あたり数秒かかる可能性がある。レイテンシ目標15秒以内は達成可能だが、サーバー起動直後の初回呼び出しは遅い場合があるため、ウォームアップ処理の検討を推奨する
- LINEエクスポートデータは個人情報・プライバシーに関わる。投入前にスタッフへの説明・同意取得プロセスを社内で設計すること
- sentence-transformers の初回起動時にモデルダウンロードが発生する（約400MB）。Phase 2のWindows移行前に事前ダウンロードしておくこと
- SaaS化時はChromaDBをそのままクラウドに持ち込まず、pgvector（PostgreSQL拡張）等のスケーラブルなベクトルDBへの移行を計画すること
- Google認証のOAuth2設定はVercelの本番ドメインが確定してから行う。開発中はlocalhost:3000を承認済みURIに追加する
