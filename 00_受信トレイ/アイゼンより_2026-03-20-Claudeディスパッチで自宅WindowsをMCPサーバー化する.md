# Claudeディスパッチで自宅WindowsをMCPサーバー化する

---

## 1. 元のアイデア整理

「Claudeディスパッチ（Claude Agent SDK）を使って、自宅のWindowsマシンをサーバーにする」というアイデア。
現在のClaudeエージェント群はMacで稼働しているが、Windowsマシンを常時稼働のサーバーとして活用することで、処理の分散・コスト削減・常時起動が可能になる。

---

## 2. 課題・背景

- 現在のエージェント環境はMac（開発機）に依存しており、Mac使用中に干渉が起きやすい
- 自宅にWindowsマシンが余剰稼働しているなら、それをサーバー化するのは合理的
- Claude Agent SDKはAPIベースのため、Windows上でも動作原理上は問題ない
- ただしMCP（Model Context Protocol）サーバーのWindows対応状況、パス・環境差異の問題がある
- 24時間稼働させるにはスリープ制御・電源管理・ネットワーク設定が必要

---

## 3. 展開案

### 案A: Windows上でMCPサーバーを直接稼働させる
- Pythonベースの既存MCPサーバー（ファイルアクセス・Calendar APIなど）をWindows上で動かす
- Claudeエージェントのエントリポイント（.claude/commands等）もWindows用に設定
- メリット: iCloudドライブ共有があれば既存Vaultと同期可能
- 懸念: iCloudのWindows同期は不安定なことがある。パス差異（/Users/...）の対処が必要

### 案B: Windowsをリモート実行ノードにする（SSH経由）
- Mac側のエージェントがSSHでWindowsに処理を投げる構成
- 重い処理（Whisper文字起こし・画像処理等）をWindowsに委譲
- メリット: 既存Mac環境を維持しつつGPUリソースを活用できる
- 懸念: SSH接続管理・認証キーの設定・ネットワーク遅延

### 案C: Windows上にWSL2環境を構築してLinuxサーバーとして使う
- WSL2（Ubuntu）上でエージェントを稼働。LinuxのMCPエコシステムをそのまま使える
- メリット: Mac/Linuxとの互換性が高く、既存スクリプトがほぼそのまま動く
- 懸念: WSL2のファイルシステムとiCloud Driveの相性確認が必要

### 案D: Windowsをスケジューラー専用ノードにする（バッチ処理特化）
- 夜間バッチ・定期タスク（バックアップ・レポート生成等）をWindows側に切り出す
- スリープしない設定にして、タスクスケジューラーで起動
- メリット: Macへの負荷を下げつつ、夜間処理を自動化できる
- 懸念: エージェント間のデータ受け渡し設計が必要

### 案E: DockerでMCPサーバーをコンテナ化してWindows上で動かす
- Docker Desktop for WindowsでMCPサーバーをコンテナとして稼働
- メリット: 環境の可搬性・再現性が高く、Mac/Windowsを問わず同一設定で動く
- 懸念: Docker Desktop導入・リソース使用量の確認が必要

---

## 4. おすすめ案

**案C（WSL2 + Linuxサーバー化）を軸に、案D（バッチ処理特化）の役割を持たせる**

WSL2上にUbuntuを立て、既存のMCPサーバー群をそのまま移植する。
iCloud同期はWindows側のiCloudアプリを使いつつ、WSL2からWindowsパスをマウントして参照する。
まず「定期タスク専用ノード」として小さく始め、安定したら役割を拡張するのが現実的だ。
